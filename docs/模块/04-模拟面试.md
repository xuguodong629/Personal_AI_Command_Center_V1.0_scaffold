# 模块 04 · 模拟面试

> 入口：侧边栏「模拟面试」/ `Ctrl+5` ｜ 前端 `frontend/src/views/InterviewView.tsx`、`lib/voice.ts`、`lib/interviewStore.ts` ｜ 后端 `app/ai.py`、`app/voice.py`、`app/interview_store.py`

## 一、面试流程逻辑

```
阶段计划（共 12 题，后端 INTERVIEW_PLAN 固定推进）
  开场与自我介绍 ① → 履历深挖（STAR 追问）④ → 专业题（渠道/经销商/回款/库存/单店模型）④
  → 压力与动机 ② → 你的反问 ①

每轮动作（POST /api/ai/interview）
  无 user_answer → 出题
  有 user_answer → 先给≤3 句即时点评【点评】，再提出下一题【提问】
  后端按题量计划推进 stage/round_no，并返回 progress（第 n / 12 题）
  末题答完 → finished=true，自动触发复盘
```

**四种面试官人格**（`INTERVIEW_PERSONAS`）

| key | 人格 | 追问风格 |
|---|---|---|
| `hr` | HR 初面 | 温和、流程化；关注匹配度、稳定性、离职原因 |
| `region_director` | 直属大区总 | 业务犀利；紧盯数据、你的具体动作与结果 |
| `boss` | 总经理/老板 | 关注格局、风险、体系成熟度与投入产出 |
| `stress` | 压力面 | 语气质疑、连续追问、刻意制造紧张感 |

**三种面试官风格**（`INTERVIEW_STYLES`，控制追问强度与是否纠缠口径）

| key | 名称 | 行为 |
|---|---|---|
| `standard` | 标准 | 按 STAR 追问，每次只追一个点，同一主题最多连追 2 次 |
| `pragmatic` | **务实型（默认）** | **不纠缠数字口径**：口径确认一次即过，重点问「你做了什么动作、覆盖多大范围、带来什么结果」；同一个数字**最多问 1 次** |
| `stress` | 压力面 | 语气可犀利、可质疑，但**仍受限**：同一主题最多连追 2 次，且只能针对事（口径/动作/结果），不得针对人 |

**面试官专业度护栏（`_interview_system` 硬性规则，防止把候选人问崩）**

| 规则 | 说明 |
|---|---|
| **追问配额** | 同一主题（尤其同一个数字/同一段经历）**最多连续追问 2 次**；第 3 次必须换角度（动作/背景/反思/迁移/换话题），并说「这个口径我先记下，后面按台账补」 |
| **口径优先** | 候选人给多口径数字（如「线上 1700 万」）时，第一个问题必须是**确认口径**（谁的口径/含哪些/你负责哪段），而不是逼细节；口径确认一次即可 |
| **禁止重复提问** | 后端用 `_asked_questions()` 从历史里提取**已问过的问题**注入提示词，硬性禁止重复同样的角度 |
| **不得否定全部** | 某条数据口径不清只针对该条提问，不得因此否定其他经历、不得贴标签 |
| **情绪/暂停处理** | 候选人出现情绪化表达或要求暂停时，先用一句话放行（「这个问题我们先跳过，后面按台账补」/「好，那我们换个话题」）再继续；**不得连续施压** |
| **反问环节边界** | 候选人反问时，以「公司对外可公开信息」为界分三类作答：可直接回答（区域目标/渠道结构/考核口径/汇报关系/作息差旅）、需 HR 确认（薪资构成/编制/期权）、不便透露；**不得反过来考核候选人** |

## 三、业务含金量引擎（`channel.py`：让面试官真的懂渠道操盘）

**解决什么问题**：早期面试官只会问「你怎么做的」「有什么成果」，候选人回一句「我赋能终端、闭环管理」就过去了——
**双方都在说套话，谁也测不出真实操盘能力**。现在给它装上渠道操盘的"结构图"。

### 3.1 十二个业务域题库（每域：口径与指标 + 高手问题 + 套话/专业对照 + 评价要点）

| # | 业务域 | 高手会问什么（节选） |
|---|---|---|
| 1 | **区域盘子与经营口径** | 盘子按什么维度拆？出货/回款/零售三个口径各多少？前三大客户占比？全年节奏（如 2:3:3:2） |
| 2 | **渠道结构与分层** | 直营/KA/区域连锁/乡镇专卖/工程/线上各占多少？哪个走量、哪个出利润？砍哪个渠道？ |
| 3 | **经销商体系与返利** | 一级商几家？月返/季返/年返各几个点、什么条件？账期几天、授信怎么定？窜货怎么罚？ |
| 4 | **终端动销与单店模型** | 一家乡镇店投入多少、月销多少台、毛利多少、几个月回本？样机比怎么定？ |
| 5 | **型号与产品梯队** | 主推型号怎么选出来的？利润款占销量/毛利多少？老品怎么清、折让几个点？ |
| 6 | **库存、账龄与现金流** | 超期 1000 台怎么构成（型号/账龄）？折让几个点、亏损谁承担？周转天数多少、DSO 多少？ |
| 7 | **工程与 KA 大客户** | 工程 800 万：账期多久、质保金几个点、垫资多少？靠什么赢标？烂尾怎么止损？ |
| 8 | **线上与渠道价格冲突** | 线上是你操盘还是代理商店铺？控价怎么落地（谁罚、罚多少）？违规型号怎么解冻？ |
| 9 | **价格体系与促销费用** | 费用率多少、花在哪？一场爆破投入多少、产出多少、ROI 多少？核销周期多久？ |
| 10 | **政策落地与营销节奏** | 以旧换新/国补怎么落到乡镇店？谁垫钱、多久回款？淡季做什么为旺季铺垫？ |
| 11 | **团队编制与考核激励** | 带几人怎么分工？考核什么、权重多少？提成怎么设计？多久能独立管片区？ |
| 12 | **渠道治理与风险控制** | 窜货怎么发现、怎么罚（谁/多少台/罚多少）？拖欠的苗头信号有哪些？合同盯哪几条？ |

阶段轮换注入（`domains_for_stage`）：履历深挖→盘子/经销商/单店/团队；专业题→渠道结构/型号/库存/费用/工程/线上/政策/动销；
压力面→库存现金/工程/线上冲突/治理。**反问阶段不注入题库**（那轮面试官只答不考）。

### 3.2 套话检测（确定性，不靠模型判断）

`analyze_answer()` 统计四类信号并给出判定：

| 信号 | 说明 |
|---|---|
| **套话词** | 强套话（赋能/闭环/抓手/打法/拉通/颗粒度/势能/全链路/组合拳…）+ 弱套话（体系化/精细化/夯实/助力…）加权计分 |
| **数字** | 出现几个数字（量级/占比/周期的最小证据） |
| **单位** | 万/台/家/个点/%/天/个月/元… |
| **业务名词** | 70+ 个真名词：回款/出货/零售/库存/周转/账龄/返利/账期/授信/窜货/控价/样机/动销/坪效/毛利/费用率/ROI/质保金/垫资/一级商/分销/导购/提成/考核/价格带/引流款/清库/以旧换新/台账… |

判定：**具体**（数字≥3 且业务名词≥4）｜ **偏泛** ｜ **缺业务细节** ｜ **套话为主**（套话分≥4 且数字≤1）｜ **过短**。
同时列出「明显缺失」：缺口径 / 缺机制 / 缺对价 / 缺可复制性。

实例（自检里的固定用例）：一段「深度赋能终端…闭环…拉通…协同发力…势能」被判定**套话为主、套话分 20.5、命中 10 个套话词**；
而「回款 3000 万（出货 3400 万、零售 2600 万）、一级商 6 家、月返 2 个点、周转 61 天、折让 11 个点、单店 8 个月回本」判定**具体**（13 个数字、9 个业务名词）。

### 3.3 面试官怎么用这些（提示词硬约束）

- **只用业务机制提问**：每个问题必须落在 **口径 / 结构 / 算法 / 对价** 四类之一；**严禁**「你怎么做的」「有什么成果」「怎么赋能的」
- **遇到套话必须戳破**：把检测结果（套话词与次数、缺失维度）注入本轮提示词，要求直接用业务问题追问对应机制
- **追问模板**（6 组，避免只会问"还有呢"）：口径 / 结构 / 算法 / 对价 / 动作 / 库存现金，各带成句模板

**实测效果**（候选人回答纯套话）

```
面试官：【点评】这段全是套话，8 个热词没有落到任何一个机制上，无法判断盘子。
       【点评】"显著提升"没有口径：是出货、回款还是零售，也没说基数。
       【提问】河南按渠道拆：KA、区域连锁、乡镇专卖、工程、线上各占多少？哪个走量、哪个出利润？
```

### 3.4 复盘新增「表七 · 业务含金量体检」

| 列 | 判定方式 |
|---|---|
| 口径是否讲清 | ✅有 / ⚠️含糊 / ❌缺 / 未涉及 + 引用原话关键词 |
| 结构是否讲清 | 渠道占比 · 客户集中度 · 型号梯队 |
| 机制与算法 | 数字怎么算 · 返利/补货/费用规则 |
| 风险与对价 | 账期/质保金/垫资/折让/毛利/费用率 |
| 可复制性 | 步骤/标准/节奏 |
| **套话命中词** | **必须使用本地检测统计出的词与次数**（不得自己编） |
| 业务化改写建议 | 给一句把套话换成业务语言的示范 |

末尾附一行汇总：**套话率 + 最该补的一个业务域**（从十二域点名）。
实测输出示例：`深度赋能×1、赋能终端×1、赋能×1、闭环×1、抓手×1、打法×1、拉通×1、势能×1（共 8 处，套话分 23.0）`，
改写建议 `把「深度赋能终端…」换成「我给 17 家乡镇店做收旧台账+导购提成改按利润款 60 元/台，单店月均从 8 台到 13 台」`。

**自检**：`backend/selfcheck_channel.py`（**19 项全通过**）——12 域完整性、每域≥3 个具体问题、题库无空问、阶段轮换、套话/具体/含糊/过短四种判定的准确性、提示词注入内容。

## 四、复盘报告（`POST /api/ai/interview/review`）

**六张表**（只依据面试记录，缺信息写「记录中未涉及」）：

| 表 | 内容 |
|---|---|
| 总评 | 总分 / 等级 / 一句话结论 / 是否建议进下一轮 / 最大亮点 / 最大短板 |
| 逐题评分 | 题号 / 问题 / 你的要点 / 内容完整 / 结构·STAR / 数据支撑 / 表达条理 / 主要问题（各 0–5） |
| 更好的答法 | 原话节选 / 改写示范（≤80 字可直接背） / 为什么更好 |
| 风险暴露 | 风险点 / 出现题目 / 面试官可能的疑虑 / 补救话术 |
| 训练清单 | 优先级 / 补强点 / 具体动作 / 练习素材 |
| **面试官提问方式评估** | 面试官的做法 / 出现题目 / 是否专业 / 为什么 / **你下次可以怎么把话题拉回来** |
| **业务含金量体检**（表七） | 见上一节 3.4：口径 / 结构 / 机制算法 / 风险对价 / 可复制性 + 套话命中词 + 业务化改写 |

**复盘的三条硬约束（都是踩坑后加的）**

| 约束 | 原因 |
|---|---|
| **只描述行为与影响，禁止人格评判与情绪化措辞** | 早期版本会写「辱骂面试官」「情绪失控」——复盘是训练工具，不该给候选人贴标签。现在改写为「使用情绪化表达并中断了面试，导致第 5–12 题信息无法采集」 |
| **未作答/中断后未进行的题目一律填「未进行」，不得填 0** | 早期把中断后的题全按 0 分，总分被压到 45，评价严重失真；现在总分**只按已答题计算**并注明「（按 N 道已答题计）」 |
| **反问环节不用 STAR 评分** | 反问本来没有 STAR 结构；该环节按「业务关注度」与「信息获取质量」评，结构列填「—」，并检查提问顺序（应先业务后薪资） |
| **必须单列评估面试官** | 重复提问、同一数字连追 ≥3 次、未先确认口径就逼细节、候选人抗议后继续施压——这些是**面试官的问题**，不能算到候选人头上 |
| **禁止丧气结论** | 一句话结论必须含「可训练点 + 下一步动作」，每条短板配可执行动作 |

## 三、语音链路

```
播报（面试官说）
  SpeechQueue 分句流式：回复按句切分（长句再按逗号切，单句≤60 字）
  → 首句先出声，边播边合成后续（edge-tts → mp3）
  → 失败回退系统 speechSynthesis
  → 支持随时打断（stop() 立即停止并清空队列）

识别（你说话）
  连续对话：ContinuousListener（Web Audio 能量 VAD）
    自动标定噪声 → 连续 3 帧(≈150ms)判定开口 → 自动录音
    → 停顿超过 silenceMs（0.5/0.8/1.2s 可选）自动收尾
    → 播放期间保持监听用于打断；播放时阈值放大 1.8× 防外放回声
  单次录音：点击开始 / 再点结束
  边说边显示：每 3 秒把累计音频交给 base 小模型增量识别 → 写入输入框 + 实时字幕
  正式识别：small 模型（可切 medium/large-v3）→ 可选 LLM 轻校对（只纠同音字/行业词）
```

| 语音配置 | 位置 |
|---|---|
| 音色（3 男声 2 女声）、语速（6 档）、识别模型 | `data/config/voice.json` + 界面 |
| 模型缓存 | `data/models/whisper`、`data/models/hf` |

**接口**：`GET /api/voice/status`、`GET/POST /api/voice/config`、`POST /api/voice/stt`（原始字节音频，支持 `?model=base`）、`POST /api/voice/tts`、`POST /api/voice/proofread`

## 四、工作区（每场面试独立存档）

左侧列表：搜索（标题/公司/对话内容）· 标签筛选（带计数）· 双击标题重命名 ·

| `POST /api/interview/sessions/{id}/auto-tag` | 让模型按内容建议 3–6 个分类标签（岗位方向/行业/公司/角色/结果） |

**存储**：`data/interview/<id>.json`，字段 = 标题 / 公司 / 面试官人格 / JD / 阶段 / 题号 / 进度 / 是否完成 / 标签 / 消息数组 / 复盘 / 创建与更新时间。一场一文件，可整体拷贝迁移。

## 五、边界与已知限制

- **识别速度**：Whisper 为整段批处理，`small` ≈0.8× 实时（说 10 秒等约 8 秒）；`medium` 更准但 ≈2× 实时。要消除等待需换流式 ASR（方案 P3b/P3c）
- **外放回声**：建议戴耳机；已加回声消除 + 播放期阈值放大，仍误触发时把「拾音灵敏度」调到低
- **麦克风权限**：首次需授权；被拒后自动退回打字模式
- 轻校对只纠错别字与行业术语，**不改语义**；不满意可关闭该开关
