# 模块 01 · 岗位雷达（含四类信号增强 + 机会池面板）

> 入口：侧边栏「岗位雷达」/ `Ctrl+1` ｜ 前端 `frontend/src/views/RadarView.tsx`、`components/PoolBoard.tsx`、`components/SignalsPanel.tsx` ｜ 后端 `backend/app/ai.py`、`signals.py`

## 一、功能逻辑（一条流水线）

```
1) 输入层
   岗位关键词（90+ 项、13 职类分组）／目标区域（全国 330+ 项，河南优先）／目标行业（110+ 项、12 大类）
   全部为「下拉多选 + 手动输入」，选择结果存 localStorage

2) 筛选层（对齐智联 / 前程无忧的筛选逻辑）
   薪资档位（9 档 + 自定义）／工作经验／学历／公司性质（可多选）／公司规模／
   发布时间（映射搜索引擎时间参数）／职位类型／福利标签（20 项）／检索范围／排除外包派遣中介

3) 信号增强开关（默认全开）
   ① 公司风险联动  ② 扩张利好  ③ 雇主口碑  ④ 政策与产业规划

4) 检索层（**按优先级分配 16–20 路预算**；`max_paths` 在四类信号全开时用满 20）
   **P0 岗位详情页定向（最高优先，让召回直接落在岗位页而不是公司页/校招页/新闻页）**
   ① `site:jobs.51job.com {区域} {岗位} {行业}`   ② `site:zhaopin.com/jobdetail …`
   ③ `site:zhipin.com/job_detail …`              ④ `site:liepin.com/job …`（按批次轮换）
   ⑤ 官方社招页定向：目标企业有官方招聘域名时 `site:recruit.midea.com / site:maker.haier.net …`，
      否则 `{企业} 社会招聘 {区域} {岗位}`（「社会招聘」是正向词，显著压低校招页占比；企业按批次轮换）
   **P1 核心路**：区域×岗位×行业（**只填省名时自动展开省内重点地市**，按批次轮换）｜ 目标企业定向 ｜
   公司性质专路 ｜ 招聘站式硬条件（职位类型/经验/学历/规模/薪资）｜ 福利标签专路 ｜
   `{区域} {岗位} {行业} 岗位职责 任职要求`（命中正文含 JD 的页面）
   **P3 四类信号**（风险/扩张利好/口碑/政策，见第四节）
   **P4 补路**（外企·500强 / 官网+五险一金，额度有余才跑）

   **条数控制（一次多出结果，避免反复检索）**
   | 目标条数 | 路数上限 | 每路召回（自动） | 说明 |
   |---|---|---|---|
   | 10 | 16 | 5 | 快速扫一遍 |
   | 20（默认） | 18 → 20（信号全开） | 7–8 | 日常 |
   | 30 | 20 | 12 | 要一次看够 |
   | 50 | 20 | 18→20 | 大范围铺开（额度与耗时最高） |
   每路召回也可手动指定（自动 / 5 / 10 / 15 / 20）。
   「换一批」= 批次 +1：轮换检索组合（含站点路与官方社招品牌）+ 把上一批的「公司·岗位」作为排除项注入，
   **结果追加到同一份报告**，不重复、不用重新配筛选。

   **手工粘贴材料模式（零额度方案）**
   折叠框里粘贴你从 DeepSeek App 联网搜索 / 招聘 App / 企业官网复制的内容 → `manual_material` 非空时**完全跳过搜索引擎**，
   材料被切成 `【粘贴材料 k】` 块（单段 ≤3000 字、最多 40 段），后续流程完全一致：词库风险扫描 → 提示词落位要求 → 四段表 → 机会池解析
   （粘贴模式下「换一批」自动禁用并说明原因）。

   **引擎容错与额度保护**
   | 机制 | 说明 |
   |---|---|
   | 结果缓存 24h | 同一（引擎+查询+参数）直接读 `data/cache/search/*.json`，重复运行不再消耗额度 |
   | **排除词不进查询** | 把 `-校招 -中介 -派遣…` 拼进查询串会让 Tavily 零召回；过滤只作为提示词指令交给模型 |
   | **`site:` 运算符查询降 num** | **免费 Serper 对运算符查询的 num 有上限**：实测 `num≥12` → HTTP 400「Query pattern not allowed for free accounts」，`num≤10` 正常。命中 `site:/inurl:/intitle:/filetype:` 时自动降到 10，并在 400 时按 5 再降级重试一次 |
   | **时间过滤自动回退** | 招聘岗位页没有可靠的「发布时间」元数据，带上 `days` 过滤会被引擎整片丢掉（实测 `site:zhaopin.com 郑州 家电 渠道经理`：days=0 → 5 条，days=7 → **0 条**，days=30 → **0 条**）。因此：`site:` 路一律不套时间过滤；其余路为空时自动去掉时间过滤重试一次，并在诊断里说明 |
   | 空路放宽重试 | 部分路为空时，用「去掉负词与括号、只留前 4 个词」的放宽查询补一次 |
   | 备用引擎自动切换 | 主引擎全部为空 → 自动用备用引擎重跑 |
   | **诊断不混进材料** | 「无结果/抓取失败」只进诊断字段；曾经它们被当成正文喂给模型，导致「有材料」误判 + 生成 0 条的空报告 |
   | **零材料即失败** | 引擎报错且 0 条材料 → 直接返回可操作错误（额度/Key/网络 + 建议），**不烧模型 token 生成没用的报告** |
   | 一键自检 | 设置页「测试检索」→ `POST /api/search/test`：一条查询告诉你 能搜到 / 额度用尽 / Key 无效 / 网络不通 |

5) 抓取层（公开页）
   trafilatura 抽正文；装了 crawl4ai 可渲染 JS 页
   · 磁盘缓存：同一 URL 24h 内不重复抓；**空结果不写缓存**（避免一次限流把 24h 缓存毒化）
   · robots.txt 明确 Disallow 的站点跳过；并发上限 6；失败回退轻量抓取重试一次
   · **抓取排序按「实测可抓性」**，别让反爬站点吃掉配额：猎聘移动岗位页(0) → 官方社招(1) → 其他(3) → 智联/51job(4)
   · **单站点抓取上限 8 页**，避免一家把配额吃光；单次最多抓 18 页（配置项 `fetch_limit`）
   · robots.txt 明确 Disallow 的站点跳过；结果附「新抓/命中缓存/robots 禁止」计数
   · **登录墙按 URL 类型判定（不再按域名一刀切）**：
     | 站点/页面 | 实测 | 处理 |
     |---|---|---|
     | 猎聘移动版岗位页 `m.liepin.com/job/<id>.shtml` | HTTP 200，正文 **2596 字，JD 关键词 10/10 命中** | ✅ 抓正文；猎聘 www 版岗位页自动规范化为移动版（同岗位的公开服务端渲染页） |
     | 猎聘列表/搜索页、BOSS、领英、拉勾、脉脉 | JS 渲染或风控页 | ⏭ 跳过，只保留检索摘要 |
     | 智联 `Security Verification` / 51job 同一拦截页 | 正文 0 字 | ⏭ 抓取排序放到最后（不占配额） |

6) **确定性岗位候选抽取（材料 → 表格这一公里交给程序，不交给模型）**
   抓完正文后，程序把**真正的岗位详情页**（`liepin/job/<id>`、`zhipin/job_detail`、`zhaopin/jobdetail|jobs`、
   `51job/<城市>/<id>.html`、`hotjob.cn/wt/…/position`、`maker.haier.net/…/socialdetail/id/…`、
   `recruit.midea.com/…jobApplication`）抽成一张表：
   `| 岗位 | 公司 | 地区 | 薪资 | 来源平台 | 链接 | JD要点 | 证据 |`，附在材料最前面。
   模型只需**一行对一行落位**，不再需要从十几份网页正文里逐列抄 14 个字段（实测：不做这一步时，
   材料里已有 27 条带 JD 的真实岗位，模型仍输出"0 条具体岗位"）。

   **JD 证据来源：正文与检索摘要都算**（取含 JD 信号且更完整的那份）。招聘站的检索摘要本身就带正文片段
   （实测 `site:jobs.51job.com` 的摘要里就有「一、核心工作职责 1.落地执行：承接渠道运营经理策略…」），
   而 51job/智联的正文常常抓不到（反爬拦截页）——只认正文会把可用证据丢掉，只认正文还容易把拦截页噪声当 JD。
   标 `_证据=已抓正文` / `摘要含JD`。

   **公司名可信性校验**：解析出的公司名必须带公司后缀（公司/集团/商贸/电器/科技/股份/店/中心…）或命中目标品牌，
   否则**留空**（空 = 材料未见）。反面案例：BOSS 标题「新乡市芸岭菌宴餐饮- 经理服务员后厨」曾被解析出公司名
   「经理服务员后厨」，于是餐饮岗位绕过了锚定雇主的行业硬门槛回到池子里。

   **池子确定性兜底**：候选清单直接送进 `jobs.verify_rows()` 判定，通过的并入 `pool`。**池子不再依赖模型抄写**
   ——实测同一批材料下模型抄写质量会波动（池子 18 ↔ 7 条），且模型偶尔把带 JD 的候选行写成「JD 要点缺失」扔进待核实。
   同时：`invalid` 绝不并入 pending（否则"餐饮后厨""货运司机"会灌进待核实，实测待核实 20 → 42）；
   池内与待核实按 **URL 归一化**去重（模型行常带 `｜[1.7]` 引用尾巴）。

7) 本地信号扫描层（`signals.py`，确定性词库，不依赖模型）
   · 公司风险词库 68 条 → 命中即标注关键词（veto / high / medium / low）+ 原话片段
   · 扩张利好词库 45 条 → 融资/上市/并购/扩产/技术突破/中标/出海…
   · 刷量词库 27 条 + 计数规则 → 长期挂出、批量发布、非直招、薪资异常、收费陷阱
       计数规则：同一公司高频出现、同标题多平台重复、平均每公司招聘条目数异常
   · 命中项同时：① 注入提示词（强制落位到表格）② 返回前端面板展示（模型漏读也能看见）

8) 评估层（模型）
   按画像权重逐维打分并分层：
   体系成熟度 25 / 发挥成长 20 / 稳定性 15 / 渠道健康 10 / 操盘体量 10 / 薪资 10 / 团队 5 / WLB 5
   分层：≥80 优先投递；60–79 谨慎；<60 直接排除；命中底线任一条直接排除
   硬性规则：行业明显不符 → 降级或排除并注明；校招/应届/实习 → 直接排除
   **风险硬规则**：命中一票否决级风险关键词的岗位，「级」列最高只能是「低⚠️公司风险」，
   分层最高只能到「谨慎」，严禁进入优先投递

9) 输出层（表二~表六为表格；表一结构化为机会池面板）
   表一 机会池总表 → 后端解析成结构化数据，前端 `PoolBoard` 渲染（见下节）
   表二 加权评分总览   表三 逐条深度解析
   表四 风险 · 刷量 · 口碑 综合判定
   表五 扩张利好与政策/产业匹配（是否真在扩人 + 国家/地方规划 + 上下游机会）
   表六 来源与检索命中清单
```

## 二、岗位真实性判定（`jobs.py`：宁可 0 条，也不用公司情报凑岗位）

**要解决的问题**：早期 `_extract_pool_rows()` 只检查「岗位不为空 + 公司不为空」，于是
「渠道/区域销售岗（JD 未覆盖，站内检索）」「公司招聘入口」「美的集团」（公司级情报）、
「公司正在扩产 → 推测要招区域经理」这类内容全被当成具体岗位塞进机会池；
而且 `_attach_scores()` 按公司名匹配，把**公司综合评分**当成了**岗位评分**。

**现在：三道确定性关卡（不依赖模型自觉）**

### 2.1 具体岗位 7 项硬门槛（全过 = `verified`，进具体岗位池）

| # | 门槛 | 判定要点 |
|---|---|---|
| 1 | **岗位名** | 必须是真实职位名（含经理/主管/总监/专员/代表/顾问/工程师/督导/运营/市场/采购/财务/人事/销售/渠道/区域/省区/片区…）；含「招聘入口/招聘主页/招聘专区/全部职位/职位列表/热门职位/职位汇总/加入我们/校招首页/相关岗位/岗位需求/人才需求/站内检索/未覆盖/行业/新闻/政策/融资/扩产/投产/上市/并购/中标/校招/应届」等词 → 直接排除；以「岗/岗位/方向/类别」结尾且无具体职位词 → 排除 |
| 2 | **公司** | 必须明确公司名；「材料未见/多个公司/相关公司/未知」等泛称 → 排除 |
| 3 | **地区** | 必须明确工作地点（郑州/河南郑州/洛阳/河南省内）；空、未知、**"全国/不限/多地/面议"** → 判"地点不具体"，不进池 |
| 4 | **地区匹配** | 必须在用户目标区域内（含"填河南→郑州/洛阳等 18 地市"的放宽）；不符 → 进待核实（测试 D） |
| 5 | **JD 要点** | 必须 ≥24 字且含职责/要求类信号词；「JD未覆盖 / JD 未覆盖 / 站内检索 / 材料未覆盖 / 信息不足 / 待核实」等占位 → 不进池 |
| 6 | **来源平台** | 必须是可识别的招聘来源（BOSS直聘/猎聘/智联/前程无忧/LinkedIn/官网招聘/公众号/人才网/人社局…）；「站内检索/招聘入口」不算 |
| 7 | **链接** | 必须是真实 URL，**或引用编号在检索材料里真实存在**（`[9.9]` 这类编造编号会被识别出来）；**公司主页 / 招聘入口链接一律不算岗位链接**（URL 含 `careers` / `companydetail` / `campus` / `socialhome` / `jobs-worldwide` / `joinus`… → 判 `pending`） |
| 8 | **行业** | **只锚定雇主字段**（公司 / 行业 / 公司性质）命中黑名单（食品·餐饮·医疗·医药·制药·地产·物业·金融·保险·教培·直播·汽车销售…）→ **直接排除**（画像偏好④）。不看 JD —— 否则 JD 里一句「食品安全」「补充医疗保险」会把正常家电岗位误杀 |

### 2.2 三档状态（`_job_status`，不删数据只归类）

| 状态 | 含义 | 去向 |
|---|---|---|
| `verified` | 7 项硬门槛全过 | **`pool.items`（今日具体岗位）** |
| `pending` | 有招聘迹象但缺 ≥1 项（缺地点/缺 JD/链接无法确认/地区不符） | `pending_jobs.items`（待核实岗位），附「未进池原因」 |
| `invalid` | 招聘入口 / 公司情报 / 行业新闻 / 政策 / 融资 / 校招 / 推测岗位 / 公司名泛称 | 排除，但统计进 `verification.invalid` 并留示例 |

### 2.3 岗位评分与公司评分彻底分离

| 评分 | 字段 | 维度 |
|---|---|---|
| **岗位评分（0–100）** | `_score` / `_layer` / `_score_parts` / `_score_reasons`（扣分原因）/ `_score_kind="岗位评分"` | 岗位真实性 30 ｜ 地区匹配 15 ｜ 岗位匹配 15 ｜ 薪资匹配 15 ｜ 经验匹配 10 ｜ 行业匹配 10 ｜ 信息完整度 5 |
| **公司监控评分** | `_company_score` / `_company_layer` | 模型的公司层面加权评分（体系 25 / 成长 20 / 稳定 15 / 渠道健康 10 / 体量 10 / 薪资 10 / 团队 5 / WLB 5） |

前端把 `_score` 显示为「岗位 N 分」、`_company_score` 显示为「公司监控 N」（仅背景参考），**不再混用**。

**三条评分口径铁律**

| 铁律 | 说明 |
|---|---|
| 薪资只看筛选器 | `薪资匹配` 只读 `ctx.salary_min/salary_max`（用户筛选器），**绝不读简历摘要**。低于下限 = 0 分；与目标区间部分重叠 = 12；高于上限 = 8；未公开 = 5；完全落在区间内 = 15 |
| 行业锚定雇主 | 行业判定**先看公司/行业/公司性质字段**，JD 只作兜底——否则「食品公司」的 JD 里写一句"要求家电渠道经验"就会把行业判成目标行业 |
| 降权只在命中时追加 | 基础 7 维度恒定；命中刷量信号（长期挂出/多平台重复/猎头代招/派遣/中介）→ 追加 **−10**；同公司本批出现 ≥3 条 → 追加 **−8** |

**行业识别：品类词 + 目标品牌**（`GOOD_INDUSTRIES` + `TARGET_BRANDS`）

只靠品类词（家电/厨电/中央空调…）会漏掉**只写品牌不写品类**的岗位 —— 实测「入职即五险一金区域销售经理 · 海尔」「网格销售 · 海尔」
因为没有"家电"二字，被判成"非目标行业"并封顶分层。因此补了一份目标品牌表（海尔/卡萨帝/统帅/美的制冷/格力/海信/TCL/老板电器/
方太/华帝/万和/A.O.史密斯/九阳/苏泊尔/格兰仕/奥克斯/博西/双喜电器/荣事达/美菱/容声/创维/康佳/长虹/火星人/亿田/添可/追觅/科沃斯/
松下电器/惠而浦/伊莱克斯/戴森…），命中即视为目标行业。

**非目标行业封顶（画像偏好④「行业明显不符 → 降为低推荐」）**

雇主与岗位都不是目标行业、也没命中用户填的目标行业时：**分层最高只能到「谨慎」，总分压到 74 以下**。
否则「亚马逊产品开发经理」「涂料区域销售」「商务产品经理（曙光信息）」会因为字段齐全（岗位/地区/薪资/JD/链接全有）
抢占"优先投递"位——实测出现过 85 分排第一。

## 三、机会池面板（`PoolBoard`：表一的呈现方式）

**为什么改**：表一有 14 列（级/岗位/公司/地区/性质/规模/薪资/福利/经验学历/发布时间/平台/链接/风险标记/JD 要点），
在 1180px 内容区里只能横向滚动、单元格挤压，几乎读不了。

**怎么做**：后端 `_extract_pool_rows()` 把表一**整行解析成结构化数据**（`pool.items`，列名 → 单元格），

前端 `PoolBoard` 渲染，并用 `stripPoolTables()` 从 markdown 里**剔除表一段落**（避免重复；表二~表六仍在下方完整报告里）。

| 能力 | 说明 |
|---|---|
| **卡片视图**（默认） | 左侧「级」色块（高=绿 / 中=蓝 / 低=灰 / 带风险=红）；标题＝岗位 + 公司；chips＝地区·薪资·经验学历·福利·发布时间·平台；风险标记单独高亮（一票否决/刷量/失信等用重色）；JD 要点两行截断；右侧「打开链接」「详情」 |

| ③ | **雇主口碑** | `{目标企业} 员工 待遇 评价 加班 提成 知乎`、`{区域} {行业} 公司 拖欠 提成 投诉 黑猫 劳动仲裁` | 口碑词库命中（投诉/维权/克扣提成/不缴社保/强制加班…） | 表四「雇主口碑」列 |
| ④ | **政策与产业规划** | 地方重点产业扶持、国家产业政策规划、产业链上下游名单、以旧换新补贴 | 政策检索路 + 词库（专精特新/小巨人/重点项目/政府补贴…） | 表五「政策与产业匹配」列；检索关键词可一键复制自查 |
| ⑤ | **刷量 / 虚假招聘** | 随基础路自动覆盖 | 27 条刷量词库 + 3 类计数规则 | 表一「级」列标「中⚠️刷量 / 低⚠️刷量」+ 表四 + 信号面板 |

**为什么把词库放进代码而不是只写提示词**：模型对「材料里明说的坏话」会漏读、会淡化；词库命中是可复算的事实，且能把关键词与原话片段直接摆到界面上。

## 五、接口

| 接口 | 作用 |
|---|---|
| `POST /api/ai/direct/radar` | 主流程：检索 + 抓取 + 信号扫描 + 评分 + 出表；返回 `content`、`signals`、`diagnostics`、`pool`（含 `items` 结构化行） |
| `POST /api/ai/direct/deep` | 二次分析（invest / screen） |
| `GET /api/signals/lexicon` | 三套词库（风险 68 / 利好 45 / 刷量 27）与含义 |
| `POST /api/signals/scan` | 对任意文本做信号扫描（可手工粘贴材料复核） |
| `POST /api/search/test` | 搜索引擎一键自检（额度 / Key / 网络） |
| `GET/POST /api/search` | 搜索引擎与筛选默认值配置 |

关键请求字段：`position_keywords / regions / industries / profile（画像提示词）/ target_companies / scope / welfare / no_outsourcing / company_tier / salary_min|max / exp_years / company_size / edu / publish_days / job_type / welfare_tags / risk_scan / growth_scan / review_scan / policy_scan / want_count（目标条数）/ per_query（每路召回，0=自动）/ batch（第几批）/ skip_seen（换一批时排除已展示项）/ manual_material（粘贴材料）`

返回体里的 `pool`：`{rows, want, batch, paths, per_query, seen[], keys[], items[]}`——
`items` 是表一的**整行结构化数据**（前端机会池面板用），`seen` 用于「换一批」去重。

## 六、数据存储

| 数据 | 位置 |
|---|---|
| 引擎与筛选默认值 | `data/config/search.json`（不入 git） |
| 画像 / 优先级 / 底线 / 权重 / 定向企业 | `frontend/public/config/local-defaults.json`（不入 git） |
| 表单输入、开关状态、上一次结果、粘贴材料 | 浏览器 localStorage（`jc-radar-inputs`、`jc-radar-scans`、`jc-radar-pool`、`jc-radar-manual`） |
| 检索结果缓存 | `data/cache/search/<sha1>.json`（24h TTL，可随时删） |
| 正文抓取缓存 | `data/cache/pages/<sha1>.json`（24h TTL，可随时删） |
| 机会池结果 | 组件内状态（不落盘）；用「下载」导出 Markdown 或「CSV」导出表格 |

## 七、提示词要点（`RADAR_SYSTEM` + 落位要求）

1. 企业质量优先（外企 / 世界500强 / 中国500强 / 地区龙头）
2. 福利优先（五险一金 > 五险 > 未提及如实标注）
3. 刷 KPI 判断（同公司同岗位多平台重复 / 常年挂出 / 批量发布）
4. 行业优先、不符者降级或排除；社招导向，校招/应届/实习直接排除
5. **联系方式合规**：只引用已公开招聘的信息，严禁个人手机号与推断号码
6. **信号落位（硬性）**：词库命中项必须逐条出现在表四；一票否决级命中必须降级到「低⚠️公司风险」；
   利好不得凭公司名气推断扩张；材料矛盾时以命中原文为准并标注冲突
7. **条数与去重**：目标条数尽量出满，材料不足时写明缺口原因；同公司同岗位多平台重复合并成一行；
   同一公司最多 3 条；按「级」+ 加权总分降序

## 八、边界与已知限制

- 检索路数上限 20 路：组合很多时只覆盖部分，其余由模型按全量清单判断并标注「本次未检索」
- **检索引擎实测可用性**（本机网络）：`ddg`（DuckDuckGo，免 Key）✅ 可用且能召回猎聘/BOSS直聘岗位页；
  Serper ✅ 可达；Tavily 额度用尽（432）、智谱余额不足（429）；**Brave 与公共 SearXNG 实例在本机超时/令牌无效**
- 词库命中是**线索**：`失信`这类词可能出现在无关新闻里，必须回到原文与官方渠道核实；界面会同时给出关键词、次数与原话片段
- 政策文件以官方发布为准（发改委 / 工信部 / 省政府规划专栏）；模型转述仅供参考
- **DeepSeek API 不能做检索**（`web_search` 工具被官方忽略、无独立搜索端点）→ 模型用 DeepSeek，检索另配引擎，或用「手工粘贴材料」
- **不做逆向爬虫**：不绕过登录墙、验证码与站点风控（法律与稳定性风险）；提升能力走合规方向——页面缓存、robots 遵守、并发限流、公开页正文抽取、更大抓取页数上限
- 引擎报错不再静默：结果顶部显示「检索诊断」（额度/Key/网络 + 原始报错可展开）
- 全流程只依据检索材料；查不到就写「材料未覆盖」，不做臆测
