# 模块 01 · 岗位雷达（含四类信号增强 + 机会池面板）

> 入口：侧边栏「岗位雷达」/ `Ctrl+1` ｜ 前端 `frontend/src/views/RadarView.tsx`、`components/PoolBoard.tsx`、`components/SignalsPanel.tsx` ｜ 后端 `backend/app/ai.py`、`signals.py`

## 一、功能逻辑（一条流水线）

```
1) 输入层
   岗位关键词（90+ 项、13 职类分组）／目标区域（全国 330+ 项，河南优先）／目标行业（110+ 项、12 大类）
   全部为「下拉多选 + 手动输入」，选择结果存 localStorage

2) 筛选层（对齐智联 / 前程无忧的筛选逻辑）
   薪资档位（9 档 + 自定义）／工作经验／学历／公司性质（可多选）／公司规模／
   发布时间（映射搜索引擎时间参数）／职位类型／福利标签（20 项）／检索范围／排除外包派遣中介

3) 信号增强开关（默认全开）
   ① 公司风险联动  ② 扩张利好  ③ 雇主口碑  ④ 政策与产业规划

4) 检索层（基础 8 路 + 信号增强最多 6 路；目标条数越大自动扩到 20 路）
   ① 区域 × 岗位 × 行业锚点   ② 目标企业定向（local-defaults 的 target_companies）
   ③ 公司性质专路            ④ 招聘网站式硬条件（职位类型/经验/学历/规模/薪资）
   ⑤ 福利标签专路            ⑥ 外企·500强专路   ⑦ 企业官网 + 五险一金   ⑧ 领英 LinkedIn
   ⑨ 公司风险专路（欠薪/失信/被执行/投诉/劳动仲裁）
   ⑩ 扩张利好专路（融资·上市·扩产·技术突破·中标）
   ⑪ 雇主口碑专路（看准·脉脉·知乎·投诉平台）
   ⑫⑬⑭ 政策与产业规划专路（地方重点产业扶持 / 国家产业政策规划 / 产业链上下游名单）
   ⑮+ 目标条数 >20 时追加：按批次轮换的区域×岗位路、行业细分路（最多到 20 路）

   **条数控制（一次多出结果，避免反复检索）**
   | 目标条数 | 路数上限 | 每路召回（自动） | 说明 |
   |---|---|---|---|
   | 10 | 14 | 5 | 快速扫一遍 |
   | 20（默认） | 14 | 7 | 日常 |
   | 30 | 17 | 12 | 要一次看够 |
   | 50 | 20 | 18→20 | 大范围铺开（额度与耗时最高） |
   每路召回也可手动指定（自动 / 5 / 10 / 15 / 20），上限 20（引擎限制）。
   「换一批」= 批次 +1：轮换检索组合 + 把上一批的「公司·岗位」作为排除项注入，**结果追加到同一份报告**，不重复、不用重新配筛选。

   **手工粘贴材料模式（零额度方案）**
   折叠框里粘贴你从 DeepSeek App 联网搜索 / 招聘 App / 企业官网复制的内容 → `manual_material` 非空时**完全跳过搜索引擎**，
   材料被切成 `【粘贴材料 k】` 块（单段 ≤3000 字、最多 40 段），后续流程完全一致：词库风险扫描 → 提示词落位要求 → 六张表 → 机会池解析
   （粘贴模式下「换一批」自动禁用并说明原因）。
   实测：4 段粘贴材料 → 出 4 条机会池，其中 2 条正确判为「低⚠️公司风险」（保证金/买产品一票否决、失信被执行人一票否决）。

   **引擎容错与额度保护**
   | 机制 | 说明 |
   |---|---|
   | 结果缓存 24h | 同一（引擎+查询+参数）直接读 `data/cache/search/*.json`，重复运行不再消耗额度 |
   | **排除词不进查询** | 以前把 `-校招 -中介 -派遣…` 拼进查询串，**Tavily 会对这种叠加直接零召回**；现在过滤只作为提示词指令交给模型 |
   | 空路放宽重试 | 部分路为空时，用「去掉负词与括号、只留前 4 个词」的放宽查询补一次 |
   | 备用引擎自动切换 | 主引擎全部为空 → 自动用备用引擎重跑 |
   | **诊断不混进材料** | 「无结果/抓取失败」只进诊断字段；以前它们被当成正文喂给模型，导致「有材料」误判 + 生成 0 条的空报告 |
   | **零材料即失败** | 引擎报错且 0 条材料 → 直接返回可操作错误（额度/Key/网络 + 建议），**不烧模型 token 生成没用的报告** |
   | 一键自检 | 设置页「测试检索」→ `POST /api/search/test`：一条查询告诉你 能搜到 / 额度用尽 / Key 无效 / 网络不通 |

5) 抓取层（公开页）
   trafilatura 抽正文；装了 crawl4ai 可渲染 JS 页
   · 磁盘缓存：同一 URL 24h 内不重复抓（实测重复运行 4.15s → 0.10s，约 41×）
   · robots.txt 明确 Disallow 的站点跳过；并发上限 6；失败回退轻量抓取重试一次
   · 登录墙平台（BOSS直聘/猎聘/领英/拉勾）跳过抓取，只保留检索摘要与站内直达链接
   · 单次最多抓 16 页（原 8 页）；结果附「新抓/命中缓存/robots 禁止」计数

6) 本地信号扫描层（`signals.py`，确定性词库，不依赖模型）
   · 公司风险词库 68 条 → 命中即标注关键词（veto / high / medium / low）+ 原话片段
   · 扩张利好词库 45 条 → 融资/上市/并购/扩产/技术突破/中标/出海…
   · 刷量词库 27 条 + 计数规则 → 长期挂出、批量发布、非直招、薪资异常、收费陷阱
       计数规则：同一公司高频出现、同标题多平台重复、平均每公司招聘条目数异常
   · 命中项同时：① 注入提示词（强制落位到表格）② 返回前端面板展示（模型漏读也能看见）

7) 评估层（模型）
   按画像权重逐维打分并分层：
   体系成熟度 25 / 发挥成长 20 / 稳定性 15 / 渠道健康 10 / 操盘体量 10 / 薪资 10 / 团队 5 / WLB 5
   分层：≥80 优先投递；60–79 谨慎；<60 直接排除；命中底线任一条直接排除
   硬性规则：行业明显不符 → 降级或排除并注明；校招/应届/实习 → 直接排除
   **风险硬规则**：命中一票否决级风险关键词的岗位，「级」列最高只能是「低⚠️公司风险」，
   分层最高只能到「谨慎」，严禁进入优先投递

8) 输出层（表二~表六为表格；表一结构化为机会池面板）
   表一 机会池总表 → 后端解析成结构化数据，前端 `PoolBoard` 渲染（见下节）
   表二 加权评分总览   表三 逐条深度解析
   表四 风险 · 刷量 · 口碑 综合判定
   表五 扩张利好与政策/产业匹配（是否真在扩人 + 国家/地方规划 + 上下游机会）
   表六 来源与检索命中清单
```

## 二、机会池面板（`PoolBoard`：表一的呈现方式）

**为什么改**：表一有 14 列（级/岗位/公司/地区/性质/规模/薪资/福利/经验学历/发布时间/平台/链接/风险标记/JD 要点），
在 1180px 内容区里只能横向滚动、单元格挤压，几乎读不了。

**怎么做**：后端 `_extract_pool_rows()` 把表一**整行解析成结构化数据**（`pool.items`，列名 → 单元格），
`_extract_score_map()` + `_attach_scores()` 再把表二的**加权总分/分层按公司名模糊挂到每一行**（`_score` / `_layer`）；
前端 `PoolBoard` 渲染，并用 `stripPoolTables()` 从 markdown 里**剔除表一段落**（避免重复；表二~表六仍在下方完整报告里）。

| 能力 | 说明 |
|---|---|
| **卡片视图**（默认） | 左侧「级」色块（高=绿 / 中=蓝 / 低=灰 / 带风险=红）；标题＝岗位 + 公司；chips＝地区·薪资·经验学历·福利·发布时间·平台；风险标记单独高亮（一票否决/刷量/失信等用重色）；JD 要点两行截断；右侧「打开链接」「详情」 |
| **紧凑表格视图** | 只留 9 个关键列（级/岗位/公司/地区/薪资/总分/风险标记/平台/链接），表头吸顶，风险行左侧色条 |
| 搜索 | 全字段匹配（公司/岗位/地区/风险关键词…） |
| 筛选 | 全部 / 只看高 / 高+中 / 仅风险刷量；可隐藏「公司与 JD 都缺失」的空行 |
| 排序 | 按推荐级（默认，同级再按总分）/ 按加权总分 / 按薪资（月薪中位数，识别 K 与「万」，并区分「年薪」口径） |
| 导出 | 一键导出 CSV（带 BOM，Excel 双击不乱码） |
| 统计 | 顶部显示总条数 + 高/中/低分布 + 带风险标记条数 |

**踩坑（都是单测抓出来的）**

| 问题 | 原因 | 修复 |
|---|---|---|
| 表一没被剔除、重复显示 | 正则用 `表一\b` 收尾 | **中日韩字符不是正则「单词字符」，`\b` 永远匹配不上** → 改为匹配后接空白/·/、/:/\|/行尾 |
| 无总分的行显示「0 分」 | `'无法计算'.replace(/[^\d.]/g,'')` → `''`，`Number('')` = 0 | 清理后为空则返回 −1（不参与排序、显示为「—」） |
| 「1.5-2万」被当成年薪折月 | 一律按 `/12` 处理 | 中文 JD 的「万」默认月薪；只有写「年薪/年包」才折月 |

**回归测试**：`frontend/scripts/pool-display.test.cjs`（8 项，直接跑 `lib/pool.ts` 的编译产物 + `scripts/fixtures/pool-items.json` 样例）——
级解析 / 薪资解析 / 总分容错 / 列模糊匹配 / 表一剔除（两种写法）/ CSV 转义 / 样例数据全量解析。

## 三、四类信号增强

| # | 能力 | 检索路 | 确定性判定 | 输出位置 |
|---|---|---|---|---|
| ① | **公司风险联动** | 区域行业 + 欠薪/失信/被执行/投诉/劳动仲裁 | 68 条风险词库命中（含 7 条一票否决：失信被执行人、破产、跑路、欠薪、收费、传销、爆雷） | 表一「风险标记」列 + 表四 + 信号面板（关键词/次数/原话片段） |
| ② | **扩张利好** | `{目标企业} 融资 上市 扩产 投资 最新`、`{区域} {行业} 企业 融资 扩产 中标 技术突破` | 45 条利好词库（融资/上市/并购/扩产/投产/中标/大单/技术突破/出海/招商…） | 表五：利好 + 时间 + 依据 + **对招聘规模的影响（是否真在扩人）** |
| ③ | **雇主口碑** | `{目标企业} 员工 待遇 评价 加班 提成 知乎`、`{区域} {行业} 公司 拖欠 提成 投诉 黑猫 劳动仲裁` | 口碑词库命中（投诉/维权/克扣提成/不缴社保/强制加班…） | 表四「雇主口碑」列 |
| ④ | **政策与产业规划** | 地方重点产业扶持、国家产业政策规划、产业链上下游名单、以旧换新补贴 | 政策检索路 + 词库（专精特新/小巨人/重点项目/政府补贴…） | 表五「政策与产业匹配」列；检索关键词可一键复制自查 |
| ⑤ | **刷量 / 虚假招聘** | 随基础路自动覆盖 | 27 条刷量词库 + 3 类计数规则 | 表一「级」列标「中⚠️刷量 / 低⚠️刷量」+ 表四 + 信号面板 |

**为什么把词库放进代码而不是只写提示词**：模型对「材料里明说的坏话」会漏读、会淡化；词库命中是可复算的事实，且能把关键词与原话片段直接摆到界面上。

## 四、接口

| 接口 | 作用 |
|---|---|
| `POST /api/ai/direct/radar` | 主流程：检索 + 抓取 + 信号扫描 + 评分 + 出表；返回 `content`、`signals`、`diagnostics`、`pool`（含 `items` 结构化行） |
| `POST /api/ai/direct/deep` | 二次分析（invest / screen） |
| `GET /api/signals/lexicon` | 三套词库（风险 68 / 利好 45 / 刷量 27）与含义 |
| `POST /api/signals/scan` | 对任意文本做信号扫描（可手工粘贴材料复核） |
| `POST /api/search/test` | 搜索引擎一键自检（额度 / Key / 网络） |
| `GET/POST /api/search` | 搜索引擎与筛选默认值配置 |

关键请求字段：`position_keywords / regions / industries / profile（画像提示词）/ target_companies / scope / welfare / no_outsourcing / company_tier / salary_min|max / exp_years / company_size / edu / publish_days / job_type / welfare_tags / risk_scan / growth_scan / review_scan / policy_scan / want_count（目标条数）/ per_query（每路召回，0=自动）/ batch（第几批）/ skip_seen（换一批时排除已展示项）/ manual_material（粘贴材料）`

返回体里的 `pool`：`{rows, want, batch, paths, per_query, seen[], keys[], items[]}`——
`items` 是表一的**整行结构化数据**（前端机会池面板用），`seen` 用于「换一批」去重。

## 五、数据存储

| 数据 | 位置 |
|---|---|
| 引擎与筛选默认值 | `data/config/search.json`（不入 git） |
| 画像 / 优先级 / 底线 / 权重 / 定向企业 | `frontend/public/config/local-defaults.json`（不入 git） |
| 表单输入、开关状态、上一次结果、粘贴材料 | 浏览器 localStorage（`jc-radar-inputs`、`jc-radar-scans`、`jc-radar-pool`、`jc-radar-manual`） |
| 检索结果缓存 | `data/cache/search/<sha1>.json`（24h TTL，可随时删） |
| 正文抓取缓存 | `data/cache/pages/<sha1>.json`（24h TTL，可随时删） |
| 机会池结果 | 组件内状态（不落盘）；用「下载」导出 Markdown 或「CSV」导出表格 |

## 六、提示词要点（`RADAR_SYSTEM` + 落位要求）

1. 企业质量优先（外企 / 世界500强 / 中国500强 / 地区龙头）
2. 福利优先（五险一金 > 五险 > 未提及如实标注）
3. 刷 KPI 判断（同公司同岗位多平台重复 / 常年挂出 / 批量发布）
4. 行业优先、不符者降级或排除；社招导向，校招/应届/实习直接排除
5. **联系方式合规**：只引用已公开招聘的信息，严禁个人手机号与推断号码
6. **信号落位（硬性）**：词库命中项必须逐条出现在表四；一票否决级命中必须降级到「低⚠️公司风险」；
   利好不得凭公司名气推断扩张；材料矛盾时以命中原文为准并标注冲突
7. **条数与去重**：目标条数尽量出满，材料不足时写明缺口原因；同公司同岗位多平台重复合并成一行；
   同一公司最多 3 条；按「级」+ 加权总分降序

## 七、边界与已知限制

- 检索路数上限 20 路：组合很多时只覆盖部分，其余由模型按全量清单判断并标注「本次未检索」
- **检索引擎实测可用性**（本机网络）：`ddg`（DuckDuckGo，免 Key）✅ 可用且能召回猎聘/BOSS直聘岗位页；
  Serper ✅ 可达；Tavily 额度用尽（432）、智谱余额不足（429）；**Brave 与公共 SearXNG 实例在本机超时/令牌无效**
- 词库命中是**线索**：`失信`这类词可能出现在无关新闻里，必须回到原文与官方渠道核实；界面会同时给出关键词、次数与原话片段
- 政策文件以官方发布为准（发改委 / 工信部 / 省政府规划专栏）；模型转述仅供参考
- **DeepSeek API 不能做检索**（`web_search` 工具被官方忽略、无独立搜索端点）→ 模型用 DeepSeek，检索另配引擎，或用「手工粘贴材料」
- **不做逆向爬虫**：不绕过登录墙、验证码与站点风控（法律与稳定性风险）；提升能力走合规方向——页面缓存、robots 遵守、并发限流、公开页正文抽取、更大抓取页数上限
- 引擎报错不再静默：结果顶部显示「检索诊断」（额度/Key/网络 + 原始报错可展开）
- 全流程只依据检索材料；查不到就写「材料未覆盖」，不做臆测
