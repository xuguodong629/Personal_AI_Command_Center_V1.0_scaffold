## 一、系统定位与设计原则

**定位**：个人 AI 指挥中心 —— 把「找工作 + 选公司 + 选行业」这件事，做成一条**可复核、可追溯、可留档**的流水线。

**七条设计原则**（决定了后面所有实现选择）：

| 原则 | 含义 | 在代码里的体现 |
|---|---|---|
| ① **确定性优先** | 能用规则算的，绝不交给模型"感觉" | `risk.py` / `industry.py` / `signals.py` 三个纯函数规则模块，同输入同输出 |
| ② **本地优先** | 数据、模型、密钥都在本机项目目录内 | 全部落在 `data/`；Whisper 模型也在 `data/models` |
| ③ **可审计** | 每个结论都能追到"依据 + 哪条规则 + 哪句话" | 报告强制标注引用编号 `[检索i.j]`；词库命中带原话片段；规则层输出命中清单 |
| ④ **人审优先** | AI 出草稿，人做决定 | 所有模块输出可下载/存档；高风险结论给的是"核实动作"而不是"结论即事实" |
| ⑤ **模型不越权** | 模型不得推翻规则层的数值判定 | 提示词硬约束 + 等级作为"下限"（只能上调不能下调） |
| ⑥ **合规红线** | 不抓登录墙、不绕风控、不采集个人手机号 | 登录墙域名清单跳过抓取；联系方式的"双重护栏"提示词 |
| ⑦ **失败要吵** | 静默失败是最坏的体验 | 引擎错误上抛为「检索诊断」；零材料直接失败；空结果不再伪装成"有材料" |

│   ├─ /api/risk/*    风控规则层（纯函数）                    │
│   ├─ /api/industry/*行业规则层（纯函数）                    │
│   ├─ /api/signals/* 词库扫描层（纯函数）                    │

│   ├─ /api/skills/*  技能包（SKILL.md）                      │
│   └─ /api/archive/* 报告归档                                │
│      │                                                     │
│      ├──② 模型：OpenAI 兼容 chat/completions（DeepSeek/GLM/Ollama/…）
│      ├──③ 检索：Tavily / 智谱 / DuckDuckGo / SearXNG / MCP / Serper / Brave / 博查
│      ├──④ 抓取：httpx+trafilatura（可选 crawl4ai 渲染 JS）

**桌面版（Tauri）**：Rust 壳启动时自动拉起 Python 后端（`CREATE_NO_WINDOW`），退出时回收；前端由后端静态伺服，所以**只有 8787 一个端口**（dev 模式才用 5173/5199）。

### 2.2 一次业务请求的通用数据流

```
用户输入（表单/筛选/粘贴材料）
   │
   ▼
前端组装请求体（含画像提示词 profile、筛选条件、开关）
   │ POST /api/ai/direct/xxx
   ▼
后端编排：
   ① 规则层先算（若能算）        → 确定性结论（分数/档位/红旗清单）
   ② 需要实时信息则检索           → N 路并行查询 → 结果缓存 → 抓公开页正文
   ③ 词库层扫材料                → 命中关键词 + 次数 + 原话片段
   ④ 拼提示词（规则结论 + 材料 + 落位要求）
   ⑤ 调模型（OpenAI 兼容）
   ⑥ 存档（报告 md + 事实 json 快照）→ data/…
   │
   ▼
前端展示：结构化面板（机会池/风险卡/五档卡）+ 完整 markdown 报告 + 信号面板 + 检索诊断
```

## 三、贯穿全系统的六个基础机制

这六个机制被所有业务模块复用，理解了它们就理解了系统 80% 的行为。

### 3.1 三层判定架构（确定性优先）

```
① 规则层（代码，可复算）      手填/解析出的**事实** → 阈值 → 分数 / 档位 / 红旗
        ↓ 注入提示词，并声明"不得推翻"
② 检索层（网络，可追溯）      多路查询 → 抓正文 → 编号引用 [检索i.j]
        ↓ 材料 + 编号
③ 模型层（LLM，会错）         只做：解释因果、补充定性、写话术、给核实动作
```

**为什么这么切**：模型会漏、会幻觉、会替对方说好话；数值类结论（实缴比例、参保人数、执行标的、增速、集中度）用规则算才可审计。模型负责它真正擅长的部分。

**等级作为下限**：规则层给出的等级/档位是**下限**。检索层若发现规则层没覆盖的一票否决事实（破产、失信、欠薪、招聘收费），模型**必须上调**等级并标注"检索层命中"；任何情况下不得下调。

### 3.2 检索引擎子系统（`ai.py`）

**支持的引擎**（`data/config/search.json` 的 `engine` 字段）：

| 引擎 | Key | 说明 |
|---|---|---|
| `ddg` | 免 Key | DuckDuckGo（`ddgs` 包）。**本机实测可用，能召回猎聘/BOSS直聘岗位页** |
| `searxng` | 免 Key | 自建 SearXNG 的 JSON API（`searxng_url`），可聚合百度/必应 |
| `mcp` | 免 Key | 把任意 MCP 工具当引擎：`mcp_server_id` + `mcp_tool` + `mcp_query_arg` |
| `tavily` | ✔ | 召回最好，免费 1000 次/月，用尽报 432 |
| `zhipu` | ✔ | 智谱 web_search，按余额计费 |
| `serper` | ✔ | Google 结果，免费 2500 次（一次性） |
| `brave` | ✔ | 免费 2000 次/月（本机实测需代理） |
| `bocha` | ✔ | 博查，国内可直连 |

**关键机制**：

| 机制 | 作用 |
|---|---|
| **结果缓存 24h**（`data/cache/search/<sha1>.json`） | 同一（引擎+查询+条数+时间范围+域名）直接读盘，重复运行**不消耗额度** |
| **排除词不进查询** | 请求级"排除外包/校招"只作为**提示词指令**，绝不拼进 query 串（Tavily 对 `-词` 叠加会直接零召回——这是实测踩出来的） |
| **空路放宽重试** | 部分路为空 → 用"去掉负词与括号、只留前 4 个词"的放宽查询补一次 |
| **备用引擎自动切换** | 主引擎全部为空 → 自动用 `fallback_engine` 重跑 |
| **诊断与材料分离** | "无结果/抓取失败"只进 `diagnostics`，**绝不混进 context**（曾导致"有材料"误判 + 生成 0 条的空报告） |
| **零材料即失败** | 引擎报错且 0 条材料 → 直接返回 `ok:false` + 人话错误 + 建议，不烧模型 token |
| **错误人话翻译** | 432→额度用尽、429→余额/限流、401/403→Key 无效、`SUBSCRIPTION_TOKEN_INVALID`→Brave 令牌复制错、超时→代理问题 |
| **一键自检** | `POST /api/search/test`：一条查询告诉你 能搜到 / 额度用尽 / Key 无效 / 网络不通 |

### 3.3 抓取子系统（公开页正文）

```
检索结果 URL 列表
   ↓ 按 host 去重、跳过登录墙域名（zhipin.com / liepin.com / linkedin.com / lagou.com / maimai.cn）
   ↓ robots.txt 检查（结论按 host 缓存，一次进程只问一次；Disallow: / 直接跳过）
   ↓ 并发上限 6（信号量）；单次最多 16 页
   ↓ 抓取：crawl4ai（可选，渲染 JS）→ 失败回退 httpx + trafilatura → 再失败回退正则
   ↓ 正文截断 4000 字，进上下文（报告里标 [网页k]）
   ↓ 结果缓存 24h（data/cache/pages/<sha1>.json）：实测重复运行 4.15s → 0.10s（约 41×）
```

**合规取向**：只抓**公开页**；不登录、不绕验证码、不碰站点风控。"性能提升"走缓存/并发/重试/页数上限，不做逆向爬虫。

### 3.4 词库信号子系统（`signals.py`，确定性）

三套词库 + 计数规则，跑在**检索到的材料**上，**不依赖模型**：

| 词库 | 条数 | 输出 |
|---|---|---|
| 公司风险 | **68** | 关键词 + 次数 + 维度 + 严重度（veto/high/medium/low）+ **原话片段** |
| 扩张利好 | **45** | 关键词 + 次数 + 类型（融资/上市/扩产/中标/技术突破…）+ 强度 |
| 刷量虚假招聘 | **27** + 3 类计数规则 | 长期挂出 / 批量发布 / 非直招 / 薪资异常 / 收费陷阱 |
| 计数规则 | — | ① 同一公司高频出现 ② 同标题多平台重复 ③ 平均每公司招聘条目数异常 |

**双重用途**：① 注入提示词，要求"必须逐条落位到表格"；② 回传前端**信号面板**展示——模型漏读了，你在界面上也看得见。

**接口**：`GET /api/signals/lexicon`（看词库全貌）、`POST /api/signals/scan`（对任意文本扫描，可粘贴材料复核）。

### 3.5 模型路由子系统

```
每次请求带 provider_id
   ↓ _load_providers() 读 data/config/ai.json
   ↓ _llm_call / _llm_call_tools → {base_url}/chat/completions（OpenAI 兼容）
   ↓ 统一错误翻译（402 余额 / 401 鉴权 / 404 地址 / 429 限流 / 超时）
```

- 供应商完全自定义（预设：智谱 GLM / DeepSeek / Ollama / Kimi / 通义 / 自定义），**换模型不改代码**
- 界面按模块记住所选模型（localStorage）
- **DeepSeek 只能当模型，不能当检索**：实测 `chat/completions` 传 `tools=[{type:"web_search"}]` 直接 422，`/responses` 的内置 `web_search` 被官方忽略，`/web_search` 端点 404

### 3.6 存档子系统（`archive.py`）

```
save_report(company/行业, content, kind, meta, facts, root)
   ↓ data/<root>/<主体名>/<YYYY-MM-DD-HHMM>-<kind>.md     报告正文（带 front-matter）
   ↓ data/<root>/<主体名>/<同名>-facts.json               事实快照（可复算/可复盘）
```

- `root` 白名单：`intelligence` / `knowledge` / `knowledge/_行业` / `projects` / `review` / `decisions` / `inbox`（防止接口被用来写任意路径）
- 文件名安全化（保留中日韩与字母数字，其余转下划线）；读写都做**路径穿越校验**
- 接口：列表 / 读取 / 删除（`GET|POST|DELETE /api/archive/reports`、`GET /api/archive/reports/read`）

## 四、模块逐个详解

### 4.1 岗位雷达（`RadarView`）

> 快捷键 `Ctrl+1`｜后端 `POST /api/ai/direct/radar`｜前端 `RadarView.tsx` + `PoolBoard.tsx` + `SignalsPanel.tsx`

**它解决什么**：把"今天有哪些值得投的岗位"变成一张**可排序、可筛选、带风险标记**的机会池。

#### 运作逻辑（八步）

**① 输入层**
- 岗位关键词（90+ 项、13 职类）、目标区域（全国 330+ 项，河南地市优先）、目标行业（110+ 项、12 大类）——全部"下拉多选 + 手动输入"
- 简历摘要（必填，作为画像依据之一）

**② 筛选层**（对齐智联/前程无忧的筛选语义）
薪资档位（9 档 + 自定义）／工作经验／学历／公司性质（8 类，可多选）／公司规模／发布时间／职位类型／福利标签（20 项）／检索范围／排除外包派遣中介

**③ 信号增强开关**（默认全开，可单独关掉省时间）
① 公司风险联动　② 扩张利好　③ 雇主口碑　④ 政策与产业

**④ 检索层**：基础 8 路 + 信号增强 6 路；目标条数大时按批次轮换扩到最多 20 路

| 目标条数 | 路数 | 每路召回（自动） |
|---|---|---|
| 10 | 14 | 5 |
| 20（默认） | 14 | 7 |
| 30 | 17 | 12 |
| 50 | 20 | 18→20 |

- **「换一批」**：批次 +1 → 轮换区域×行业组合 + 把上一批的「公司·岗位」作为排除项注入 → 结果**追加到同一份报告**（不重复、不用重配筛选）
- **手工粘贴材料**：填了就**完全跳过搜索引擎**，材料切成 `【粘贴材料 k】` 块（后续流程完全一致）→ 零额度也能跑

**⑤ 抓取层**：命中公开页抓正文补全 JD（登录墙平台只留摘要与直达链接）

**⑥ 词库扫描层**：风险/利好/刷量三套词库扫材料 → 命中即标注 + 回传前端面板

**⑦ 评估层（模型）**：按画像 8 维加权打分

| 维度 | 权重 | 维度 | 权重 |
|---|---|---|---|
| 体系成熟度 | 25 | 体量匹配 | 10 |
| 发挥成长 | 20 | 薪资 | 10 |
| 稳定性 | 15 | 团队 | 5 |
| 渠道健康 | 10 | WLB | 5 |

分层：**≥80 优先投递｜60–79 谨慎｜<60 直接排除｜命中任一底线直接排除**

硬规则：
- 行业明显不符 → 降级或排除并注明
- 校招/应届/实习 → 直接排除
- **命中一票否决级风险关键词 → 「级」列最高「低⚠️公司风险」，分层最高「谨慎」，严禁进优先投递**

**⑧ 输出层**：表一（机会池总表）+ 表二加权评分 + 表三逐条深度解析 + 表四风险·刷量·口碑 + 表五扩张利好与政策匹配 + 表六来源清单

#### 表一怎么呈现：机会池面板（`PoolBoard`）

后端把表一**整行解析成结构化数据**（`pool.items`），并把表二的**加权总分/分层按公司名挂到每一行**；前端渲染两种视图：

| 视图 | 内容 |
|---|---|
| **卡片（默认）** | 级色块 → 岗位 + 公司 → chips（地区·薪资·经验学历·福利·时间·平台）→ 风险标记高亮 → JD 要点 → 打开链接 / 详情 |
| **紧凑表格** | 9 个关键列，表头吸顶，风险行左侧色条 |

工具条：搜索、按级筛选（全部/只看高/高+中/仅风险）、排序（级/总分/薪资）、隐藏信息缺失行、导出 CSV、条数统计。
markdown 里的表一段落会被**剔除**（避免重复），表二~表六仍在下方完整报告里。

#### 二次分析（机会池生成后）

| 按钮 | 接口 | 逻辑 |
|---|---|---|
| 投资视角 · 潜力企业深挖 | `/api/ai/direct/deep` `mode=invest` | 五步：赛道判断（顺势 + 时光机）→ 潜力清单（80/20 仓位）→ 五张尽调卡（市场/增长/团队/单位经济/现金流）→ 逆向否决 + 价值判断 → 建仓名单（重仓/观察/卖出） |
| 优秀企业筛选（6 步） | `mode=screen` | 画像校准 → 目标企业画像 → 8 维筛选清单 → 加权打分表 → 避坑清单 + 话术 → 决策建议 |

### 4.2 行业赛道（`IndustryView`）

> 快捷键 `Ctrl+2`｜`POST /api/ai/direct/industry`｜`industry.py`

**它解决什么**：这个行业现在处在生命周期哪一档，**我进去划不划算**。

#### 五档判据

| 档位 | 分数 | 特征 | 进入结论 |
|---|---|---|---|
| **新势力 / 风口期** | ≥80（过门槛） | 新需求、格局未定、资本密集 | 可进，但按风投标准（先问现金够发几个月、融资到账、前任去向） |
| **蓝海朝阳（成长期）** | 65–79 | 渗透率抬升、格局初定、政策扶持 | **最佳窗口**：体系搭建期，区域负责人价值最大 |
| **平稳存量（成熟期）** | 45–64 | 增速同步 GDP、集中度较高 | 稳健：**只进龙头或细分第一** |
| **红海内卷（饱和期）** | 25–44 | 价格战、同质化、毛利下滑 | 谨慎：核实提成兑现与账期，不接"无体系开荒" |
| **夕阳没落（衰退期）** | <25 | 需求萎缩、批量退出 | 不建议：优先能力迁移 |

#### 规则层：17 个事实字段 → 15 项加权

需求信号 25 ／ 行业增速 15 ／ 政策方向 12 ／ 价格战程度 12 ／ 毛利率趋势 10 ／ 融资事件数 10 ／ 产能供需 6 ／ 玩家数量变化 6 ／ 招聘趋势 6 ／ 上市过会数 5 ／ 补贴依赖 5 ／ 薪资趋势 4 ／ 技术替代 4 ／ 出口出海 4 ／ 区域产业基础 4

**两道闸门**：
1. **新势力门槛**：只有「需求爆发」或「增速≥30% 且融资≥15 起」或「玩家大量增加且需求爆发」才算风口；否则分数再高也压回蓝海朝阳
2. **硬性上限**：政策强限制 / 恶性价格战+毛利下滑 / 产能过剩+需求放缓 → 上限红海内卷；需求萎缩+负增长 → 上限夕阳没落；需求放缓+招聘收缩 → 上限平稳存量

#### 词库交叉验证

五档特征词（风口词 / 渗透率 / 以旧换新 / 价格战 / 去产能…）扫材料，与规则层互证。
注意已做两个校正：**剔除检索式回显**（否则等于把自己的提问算成行业特征）+ **按键词数归一**；且明确"词频只作参考，档位以规则层为准"。

#### 输出与存档

- 8 路检索：规模增速 / 融资 / 价格战 / 产能 / 政策 / 集中度 / 招聘 / 区域产业基础
- 五节报告：赛道判定 → 需求与增速 → 竞争格局 → 政策与产业链 → 进入时机与个人动作（投递优先级 / 选什么岗 / 谈薪避坑 / 先核实哪 3 件事）
- 存档：`data/knowledge/_行业/<行业>/<时间>-行业赛道研判.md` + facts 快照（**可按时间对比档位迁移**）

### 4.5 模拟面试（`InterviewView`）

> 快捷键 `Ctrl+6`｜`POST /api/ai/interview`、`/review`、`/api/interview/sessions/*`、`/api/voice/*`

**它解决什么**：把"面试"练到能自动化——出题、追问、点评、复盘，并**每场独立存档**。

#### 四种面试官人格（+ 三种风格）

| id | 人格 | 关注点 |
|---|---|---|
| `hr` | HR | 匹配度、稳定性、离职原因 |
| `region_director` | 直属大区总 | 数据、具体动作与结果 |
| `boss` | 总经理/老板 | 格局、风险、体系成熟度、投入产出 |
| `stress` | 压力面 | 质疑、连续追问、制造紧张 |

**面试官风格**（`style`）：`standard` 标准 ｜ `pragmatic` **务实型（默认，不纠缠数字口径）** ｜ `stress` 压力面（语气犀利但仍受限）。

**面试官专业度护栏**（防止把候选人问崩，也防止"不专业的提问被算成候选人的错"）：
① **追问配额**——同一主题最多连追 2 次，第 3 次必须换角度；② **口径优先**——多口径数字先问"这是谁的口径"；
③ **禁止重复提问**——后端提取已问题目注入提示词；④ 某条数据不清不得否定其他经历；
⑤ 候选人情绪化或要求暂停时先放行再换话题，不得连续施压；⑥ 反问环节以公司公开信息为界作答、不得反考候选人。

**业务含金量引擎**（`channel.py`，让面试官真的懂渠道操盘）：
- **12 个业务域题库**：区域盘子与口径／渠道结构与分层／经销商与返利／终端动销与单店模型／型号梯队／库存账龄与现金流／工程与 KA／线上与渠道冲突／价格与促销费用／政策落地与节奏／团队与考核／渠道治理，每域含"口径与指标 + 4 个高手问题 + 套话/专业对照"
- **只用业务机制提问**：每个问题必须落在 **口径 / 结构 / 算法 / 对价** 四类之一，**严禁**问"你怎么做的"
- **套话检测**（确定性）：强/弱套话词加权 + 数字 + 单位 + 70 余个业务名词 → 判定「具体 / 偏泛 / 缺业务细节 / 套话为主 / 过短」，并列出缺口径、缺机制、缺对价、缺可复制性
- **追问模板 6 组**：口径 / 结构 / 算法 / 对价 / 动作 / 库存现金
- 实测：面对"深度赋能终端、闭环管理"这类回答，面试官直接回「这段全是套话，8 个热词没有落到任何一个机制上」，接着问「KA、区域连锁、乡镇专卖、工程、线上各占多少？哪个走量、哪个出利润？」

**复盘七张表**：总评 / 逐题评分 / 更好的答法 / 风险暴露 / 训练清单 / **面试官提问方式评估** / **业务含金量体检**。
三条硬约束：**未进行的题填「未进行」不计 0 分**（总分只按已答题算）、**反问环节不用 STAR 评分**、**禁止人格评判与丧气结论**；
表七的「套话命中词」必须引用本地检测统计值，末尾给出**套话率 + 最该补的业务域**。

#### 12 题阶段计划

开场与自我介绍 **1** → 履历深挖（STAR 追问）**4** → 专业题（渠道/经销商/回款/库存/单店模型）**4** → 压力与动机 **2** → 你的反问 **1**
→ 走完自动进入 `done`（可出复盘报告）。回合接口每次返回 `stage / round_no / stage_label / progress`。

## 五、端到端典型流程

### 流程 A：从"找工作"到"去面试"

```
① 设置 → 测试检索（确认能搜到）→ 添加模型
② 岗位雷达：选关键词/区域/行业 + 筛选条件 + 目标条数 20 → 开始搜索
      ↳ 机会池面板：先看「级=高」的，按总分排序，风险标记扫一眼
      ↳ 不够就「换一批」（自动排除已展示）
③ 对 2–3 家感兴趣的 → 「下一步：公司背调」→ 在背调页填工商事实 → 一键体检（秒回）
      ↳ 命中一票否决 → 直接放弃；黄/橙 → 按"核实动作"逐条问
④ 拿到 JD → 「定制简历」出一岗一版
⑤ 「模拟面试」按该公司人格练一轮 → 复盘报告 → 把高频追问补进简历
⑥ 真实面试后 → 「行业赛道」看这个行业值不值得长期待（存档对比档位变化）
```

### 流程 B：纯风控尽调（合作/投资视角）

```
公司背调 → 手填 52 项公开事实（关键 12 项就能出结论）→ 本地规则层秒出红旗+风险分+等级
   ↓ 有引擎额度：跑「完整背调」补定性维度（空壳/换壳/口碑/骗局）
   ↓ 没额度：用「手工粘贴材料」把企查查/裁判文书/投诉平台内容粘进来，照样出 18 维度矩阵
   ↓ 需要联系人：「触点地图」出公开招聘入口 + 法定披露 + 触达话术（不给个人手机号）
   ↓ 报告与事实自动存档 data/intelligence/<公司>/
```

### 流程 C：选行业（长期决策）

```
行业赛道 → 手填 17 个行业事实 → 本地规则判定（秒回）→ 五档速查卡定位
   ↓ 跑一次赛道研判 → 五节报告（需求/格局/政策/进入时机）→ 存档
   ↓ 3–6 个月后重跑同一行业 → 对比 front-matter 里的档位与分数 → 判断赛道是否变差
```

### 8.1 启动

| 方式 | 命令 | 说明 |
|---|---|---|
| 普通版 | `启动.bat` | 首次会建 `.venv` 装依赖，然后起后端并开浏览器 |

### 8.3 常见故障对照表

| 现象 | 根因 | 处理 |
|---|---|---|
| 状态卡「后端未启动 :8787」 | 后端没起 | `启动.bat` 或重启桌面窗口 |
| 新接口 404/405 | 旧后端进程占着 8787 | `停止.bat` 后重启（**Python 改动必须重启**） |
| 检索"没结果" | 引擎额度/Key/网络 | 设置 →「测试检索」一秒定位；或切免 Key 的 `ddg` |
| 报告里全是「材料未见」 | 引擎零结果（曾因诊断被当材料） | 已修：现在会直接把原因抛到界面；也可用「手工粘贴材料」 |
| 出现 503 | 系统代理劫持 localhost | 把 `127.0.0.1` 加入代理例外 |
| 外链一点就关程序 | WebView 被导航走 | 已修：外链走后端 `webbrowser.open` |
| 中文变乱码（脚本读取） | JSON 未声明 charset | 已修：所有响应带 `charset=utf-8` |

### 8.4 两条铁律（血泪教训，写在 README）

1. **改 UTF-8 文件不要用 PowerShell 整体读写**（`Get-Content -Raw` + `Set-Content`）——中文会按 CP936 解码后再写回，造成不可逆乱码。用编辑器或 Python。
2. **改完 Python 必须重启后端**——桌面壳会复用已在跑的实例，旧进程让新代码不生效。

## 九、边界、合规与已知限制

### 合规红线（系统层面强制）

- **不抓登录墙平台**（BOSS直聘/猎聘/领英/拉勾/脉脉）：只保留检索摘要 + 官方站内直达链接
- **不绕过验证码与站点风控**；不做逆向爬虫（法律与稳定性双重风险）
- **不采集个人手机号**：联系方式只引用已公开招聘的信息；严禁推断/拼接号码；查不到就写"未查到 + 去哪查"
- **不买号库、不社工、不爬登录墙后数据**
- 报告是**决策辅助**，不构成法律意见；劳动争议/合同纠纷请咨询专业人士

### 技术与数据限制

- 阈值是**启发式经验值**，不是法定标准：命中红旗代表"值得核实"，只有一票否决那几项属确定性负面事实
- 词库命中是**线索**（"失信"可能出现在无关新闻里），界面同时给关键词、次数与原话片段供人工判断
- 行业规模/增速等数据需来自公开报告；填不出来就留空，系统会列出缺失项并降低置信度
- 政策文件以官方发布为准（发改委/工信部/省政府规划专栏）；模型转述仅供参考
- 检索引擎额度是外部的：Tavily 1000 次/月、Serper 2500 次一次性、Brave 2000 次/月、免 Key 的 ddg 无限但质量中等
- **DeepSeek API 不能做检索**（内置 `web_search` 被忽略、无独立端点）
- 语音：本地 Whisper 是整段批处理，**每轮仍需等识别**；更快需要流式 ASR（P3b/P3c 未实现）
- 未实现（规划中）：Agents 层（把雷达/背调/面试注册为可复用 agent）、按用途绑定模型、单文件 sidecar 打包

### E. 关键阈值速查（风控）

| 条件 | 判定 |
|---|---|
| 注册 ≥1000 万且实缴 <5% | 高：撑门面/凑门槛，可动用资金有限 |
| 成立 ≥3 年仍零实缴 | 高：股东未真实投入，赔付能力弱 |
| 执行标的 ≥ 注册资本 | 高：债务超出资本承受力 |
| 参保 0 人 / < 宣称规模 20% | 高：社保与规模真实性存疑 |
| 成立 <1 年 + 注册 <200 万 + 参保 ≤3 | 高：新壳三重叠加 |
| 空壳信号 ≥3 项（集群注册/参保≤3/无官网/无案例/同址≥5家） | 高：实体经营真实性存疑 |
| 已注销关联企业 ≥3 家 | 高：做烂一家换一家 |
| 司法案件 ≥5 且年均 ≥2 | 高：履约/结算长期争议 |
| 合同纠纷 ≥5 / 借贷纠纷 ≥3 / 被执行 ≥3 / 劳动争议 ≥5 | 高：分别指向拖上游、资金链、强制执行、薪酬纠纷 |
| 曾用名 ≥2 / 法人变更 ≥3 / 动产抵押 ≥3 | 中：分别指向换壳、背锅法人、现金紧张 |

### F. 术语表

| 术语 | 含义 |
|---|---|
| **规则层** | 用代码阈值算结论的确定性层（`risk.py`/`industry.py`） |
| **词库层** | 关键词命中扫描（`signals.py`），输出线索而非结论 |
| **一票否决** | 命中即判最高风险等级、禁止给出"可以放心"结论的硬红线 |
| **换一批** | 批次 +1：轮换检索组合 + 排除已展示条目，结果追加到同一报告 |
| **粘贴材料模式** | 跳过搜索引擎，用你粘进来的内容跑同一套流水线 |
| **检索诊断** | 引擎层错误的可读解释（额度/Key/网络 + 原始报错） |
| **画像（profile）** | 候选人画像/优先级/底线/评分权重，来自 `public/config/local-defaults.json` |
