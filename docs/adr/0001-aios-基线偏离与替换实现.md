# ADR 0001：AIOS 基线偏离与替换实现

> 范围：为对齐 `AIOS_Master_Prompt_V1.0.md`（以下简称"规范"）而引入的与 §4 技术基线的偏离。
> 规范 §4 明确允许「若已有项目技术栈不同，允许替换实现框架，但必须保留本规范中的分层、接口、语义和安全要求」，
> 因此以下偏离均在允许范围内，但按 §32 要求留痕。
> 状态：已采纳（2026-09-22）

## D1. 前端：React 19 + Vite + 自研 CSS，而非 Next.js + Tailwind

- **规范**：§4 前端 = Next.js + TypeScript + Tailwind CSS，仅通过 BFF/API 访问后端。
- **现状**：既有前端是 React 19 + Vite + 自研 CSS 变量体系（2069 行），由 Tauri 桌面壳加载，后端单进程托管 `frontend/dist`。
- **理由**：无 SSR/SEO 需求；桌面端要求单进程零 Node 常驻；重写前端会把已验证的雷达/背调/面试交互全部推倒。
- **代价与补偿**：没有 BFF，前端直连 API，因此**契约责任落在后端**：`/api/v1` 全部端点声明 `response_model`、
  统一 `{data,meta}` / `{error{code,message,details,request_id}}` 封装，便于前端做单一适配层。
- **复核条件**：若引入多端（移动/网页公开版）或需要服务端渲染，再评估 Next.js。

## D2. 主数据库：默认 SQLite，可一键切 PostgreSQL 16

- **规范**：§4 主数据库 PostgreSQL 16（UUID 主键、UTC 时间、JSONB 仅用于弹性字段）。
- **现状**：`DB_URL` 默认 `sqlite+pysqlite:///data/aios.db`；模型使用 SQLAlchemy 2.x 通用类型
  （`String(36)` UUID、`DateTime(timezone=True)` UTC、`Text/JSON`），**表结构由 Alembic 迁移管理**（§30.7）。
- **理由**：本地优先 + 一键运行（§3.1/§28）；用户机器上没有 Docker/PG；SQLite 足以支撑个人规模（当前 15 条职位、
  数十条审计与作业记录）。
- **代价与补偿**：SQLite 无 JSONB、无并发写入优势；因此
  ① 所有可筛选字段结构化列化并建索引（§11.7）；
  ② 写路径短事务、无长事务；
  ③ 切库只需改 `DB_URL=postgresql+psycopg://...` 并装驱动，迁移脚本对两种方言通用。
- **复核条件**：并发写（多进程 worker）或数据量上量（>10 万职位）时切 PG。

## D3. 队列与 Worker：进程内常驻 worker 线程，而非 Redis + Celery/Arq

- **规范**：§4 缓存/队列 = Redis + Celery 或 Arq；§19 要求幂等键、重试、死信、调度与来源预算。
- **现状**：`job_executions` 表 + 常驻 worker 线程（`aios/modules/jobs/worker.py`）+ 事件循环，
  轮询领取到期作业；`scheduled_jobs` 表已建（声明式调度定义），调度派发待接。
- **理由**：不引入 Redis/Celery 可让"打开即用"成立；规范关心的是**语义**（立即返回作业卡片、幂等、退避重试、
  死信、可观测），这些已由表 + worker 实现并有测试覆盖。
- **代价与补偿**：单进程领导者（§19.1）；进程崩溃的 `running` 作业由 `claim_due` 的孤儿回收逻辑在 10 分钟后重排；
  无跨进程限流，来源限速在单个 worker 内按 `policy.rate_limit_per_minute` 生效。
- **复核条件**：需要多进程消费或跨机部署时切 Celery/Arq（作业表结构可直接复用）。

## D4. 目录结构：`backend/aios/**` 而非 `apps/api + packages/modules`

- **规范**：§7 目录树为 `aios/apps/{api,worker,web}` + `aios/packages/{core,contracts,modules/*,integrations}`。
- **现状**：新增 `backend/aios/{core,contracts,modules/{audit,jobs,jic,ai_gateway,platform},api}`，
  与既有 `backend/app/*` 并存；测试在仓库根 `tests/{unit,integration}`（与 §7 的 `tests/` 位置一致）。
- **理由**：§30.1 要求"最小化改动、禁止无故重写已有模块"——既有 `app/` 是已上线且正在使用的代码。
- **补偿**：新代码**严格按 §6 分层**（Presentation=`api/`，Application=`modules/*/application.py`，
  Domain=`*/domain/*.py`，Infrastructure=`*/infrastructure/*`，Workers=`modules/jobs/worker.py`），
  跨模块依赖只走 `aios/contracts`；`app/main.py` 只加 3 行挂载 `/api/v1`。
- **复核条件**：若 `app/` 逐步被 `aios/modules/*` 取代，可整体迁移到规范目录树。

## D5. 运行时：Python 3.10，而非 3.12

- **规范**：§4 后端 = Python 3.12。
- **现状**：本机 `backend/.venv` 为 Python 3.10.11。
- **代价与补偿**：3.10 不支持 f-string 内反斜杠、`X | Y` 在运行时可用的部分新特性等；
  代码已按 3.10 语法约束编写（`from __future__ import annotations` + `ruff target-version=py310`）。
- **复核条件**：升级解释器到 3.12 后无需改代码，仅需重装依赖并把 `target-version` 调高。
