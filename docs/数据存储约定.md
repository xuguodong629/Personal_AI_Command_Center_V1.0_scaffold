# 数据存储约定（本地优先 · 模块分仓）

> 原则：**一切数据都在本机项目目录内**（可整体打包/迁移/备份），密钥只落在 `data/config/`，且 `data/` 默认不入 git。

## 一、总览

```
Personal_AI_Command_Center_V1.0_scaffold/
├─ data/                     ← 全部运行时数据（.gitignore 忽略，仅保留各目录 README.md）
│  ├─ config/                密钥与参数：ai / search / voice / mcp / contact
│  ├─ models/                本地模型/听写模型缓存（首次使用自动下载）
│  ├─ cache/                 第三方工具缓存（npm / huggingface 等）
│  ├─ interview/             模拟面试工作区：一次面试 = 一个 json
│  ├─ skills/                技能包：一个技能 = 一个目录（SKILL.md）
│  ├─ inbox/                 收件箱：未整理的原始素材
│  ├─ knowledge/             长期知识库：方法论、行业认知、模板
│  ├─ intelligence/          情报与背调：公司背调、行业简报、触点地图
│  ├─ projects/              项目/求职进程：一个机会 = 一个目录
│  ├─ decisions/             决策记录：关键选择与依据
│  ├─ review/                复盘：日/周/月、面试复盘
│  ├─ database/              结构化数据：CSV/JSON/SQLite 表格数据
│  └─ logs/                  运行日志副本（可随时清理）
└─ frontend/public/config/   界面默认值（人格、筛选偏好、评分权重）——同样不入库
```

## 二、分仓职责与命名

### 1. `data/config/` — 配置与密钥

| 文件 | 内容 | 敏感度 |
|---|---|---|
| `ai.json` | 模型供应商（含 API Key）、默认模型 | 高 |
| `search.json` | 搜索引擎 Key、时间范围、域名白/黑名单、抓取器 | 高 |
| `voice.json` | 音色、语速、识别模型 | 低 |
| `mcp.json` | MCP 服务器（command/args/env/url） | 中高 |
| `contact.json` | 付费工商数据源预留位 | 高 |

- 界面「设置」里改，写回这里；**改完即时生效**（无需重启）。
- 备份/迁移时，这个目录要单独加密保存；对外分享项目请先清空。

### 2. `data/models/`、`data/cache/`

- `models/`：faster-whisper 等模型权重，首次使用自动下载（默认走 hf-mirror）。
- `cache/`：`npm/`（MCP 的 npx 包）、`huggingface/`（HF 下载缓存）。
- **可随时删除**，删了会按需重新下载；不影响业务数据。

### 3. `data/interview/<id>.json` — 一次面试一个文件

```jsonc
{
  "id": "…", "title": "…", "company": "…", "position": "…",
  "tags": ["…"], "created_at": "…", "updated_at": "…",
  "mode": "text | voice | live",
  "turns": [ { "role": "interviewer|me", "text": "…", "at": "…" } ],
  "review": { "…结构化点评…" }
}
```

- 支持列表 / 检索 / 打标签 / 自动标签 / 重命名 / 删除；界面可折叠、可切换工作区。
- 想清理历史：直接删文件或界面里删，互不影响。

### 4. `data/skills/<name>/SKILL.md` — 一个技能一个目录

- 目录内可再加脚本、模板、示例；`SKILL.md` 是注入模型的指令正文。
- 支持界面新建/编辑/删除、从 URL 导入公开技能。

### 5. 知识型目录：`inbox / knowledge / intelligence / projects / decisions / review`

| 目录 | 放什么 | 命名建议 |
|---|---|---|
| `inbox/` | 刚抓下来的 JD、截图转文本、聊天记录片段——**还没整理** | `YYYY-MM-DD-<来源>-<主题>.md` |
| `knowledge/` | 方法论、行业认知、话术模板、可复用清单；**行业赛道研判报告**（`_行业/<行业>/`） | `<主题>/<文档>.md` |
| `intelligence/` | 公司背调报告、行业情报简报、触点地图 | `<公司名>/<YYYY-MM-DD>-背调.md` |
| `projects/` | 一个机会一个目录：JD、简历版本、面试记录、往来时间线 | `<公司>-<岗位>/` |
| `decisions/` | 关键选择（接不接、报价、优先级调整）：背景/选项/依据/结论/复盘日期 | `YYYY-MM-DD-<决策主题>.md` |
| `review/` | 日/周/月复盘、面试复盘、模块使用复盘 | `YYYY-Www-复盘.md` |

### 6. `data/database/` — 表格型数据

- 岗位库、公司库、联系人库等 CSV / JSON / SQLite。
- 由 AI 助手或技能生成，也可直接喂给 SQLite MCP 服务器查询。
- **合规红线**：不收录个人手机号等个人敏感信息（参见 README「边界与合规」）。

### 7. `data/logs/`

- 后端启动/报错、检索诊断、任务执行日志副本；仅用于排查问题，可定期清空。

## 三、流转关系（建议习惯）

```
抓取/粘贴 → data/inbox/（原始）
              ↓ AI 助手整理、去重、补全
    knowledge/（可复用认知）  intelligence/（针对公司/行业）
              ↓ 形成具体行动
    projects/<公司-岗位>/（JD + 简历版本 + 面试记录）
              ↓ 关键节点做选择
    decisions/（记下依据）  review/（定期回看）
              ↓ 结构化沉淀
    database/（可查询的表格）
```

## 四、备份、迁移与安全

| 事项 | 做法 |
|---|---|
| 备份 | 整个项目目录复制即可（`data/` 含密钥，建议加密存放） |
| 迁移到新机器 | 复制项目 → 用 `启动.bat` 首次运行会自动建 `.venv` 装依赖 → 密钥随 `data/config/` 一起带过去 |
| 分享/上传 | **先删 `data/config/`**（含 API Key）；`data/` 已在 `.gitignore` 中，默认不会提交 |
| 换模型/换电脑 | 模型与缓存都在 `data/models`、`data/cache`，可选携带，省下载时间 |
| 体积控制 | `data/models` 通常最大（数百 MB~GB）；`cache`、`logs` 可随手清 |

## 五、不入库规则（`.gitignore`）

```
data/*
!data/*/
data/*/*
!data/*/README.md
```

即：`data/` 下**所有内容都不入库**，只保留每个目录里的 `README.md` 说明文件，保证仓库克隆后目录结构清晰、但没有任何密钥与个人数据。
