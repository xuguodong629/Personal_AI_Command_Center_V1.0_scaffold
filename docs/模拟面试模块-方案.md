# 模拟面试模块 · 设计方案（未实施）

> 状态：**方案待评审**（本文档只做设计，尚未改动任何代码）
> 归属模块：AI 助手（`ChatView`）
> 语音方案：**本地 Whisper 识别（STT）+ edge-tts 合成（TTS）** —— 免费、离线、隐私好
> 复用资产：`local-defaults.json` 候选人画像 / 雷达机会池与 JD / 深度分析提示词 / 底线清单（hard_rules）

---

## 一、目标与定位

把「AI 助手」从"问答"升级为"**可以陪你练面试的面试官**"：

- 按**真实岗位 JD + 你的画像**出题，而不是通用题库
- **分阶段推进**（自我介绍 → 履历深挖 → 专业题 → 压力题 → 反问）
- **语音对练**：面试官说、你回答，全程不用打字
- 结束产出**可执行的复盘报告**（逐题评分 + 更好答法 + 表达节奏 + 训练建议）

---

## 二、用户流程（时序）

```
选择模式：AI 助手 → 模拟面试
  ① 选面试官角色（HR 初面 / 直属大区总 / 老板终面 / 压力面）
  ② 选依据：当前机会池中的某条 JD（可一键带入）+ 画像（默认徐国栋画像）
  ③ 点「开始面试」
        ↓
  面试官语音开场 → 依次提问，每题：
       用户录音（点击说话 / 按住说话）→ WAV → 后端 Whisper 识别 → 文本
       文本追加进会话 → LLM 生成：即时点评（≤3 句）+ 追问或下一题 → TTS 播报
       界面显示：当前阶段 / 第 N 题 / 计时 / 识别文本（可手改）
        ↓
  进入「你的反问环节」→ 结束
        ↓
  生成《面试复盘报告》（表格）→ 可下载 Markdown / 存入本地记录
```

## 三、架构与数据流

```
┌──────────────── 前端（React，Tauri WebView2） ────────────────┐
│ ChatView：模式切换（对话 / 模拟面试）                          │
│  · 录音：AudioContext 采集 → 16kHz 单声道 WAV（无需 ffmpeg）   │
│  · 播放：<audio> 播放后端 TTS 返回的 mp3                      │
│  · 状态机：idle → asking → listening → reviewing → next …     │
└──────────────────────────┬───────────────────────────────────┘
                           │ HTTP（本地 8787）
┌──────────────────────────▼───────────────────────────────────┐
│ FastAPI backend                                               │
│  · POST /api/voice/stt   音频(WAV) → 文本（faster-whisper）    │
│  · POST /api/voice/tts   文本 → mp3（edge-tts，中文音色）      │
│  · POST /api/ai/interview  回合逻辑：出题 / 点评 / 追问        │
│  · POST /api/ai/interview/review  生成复盘报告                │
│  · 会话状态：内存 + 落盘 data/interview/*.md（复盘）           │
└──────────────────────────────────────────────────────────────┘
```

**为什么前端出 WAV**：WebView2 的 `MediaRecorder` 默认输出 webm/opus，后端解码需 ffmpeg；改用 WebAudio 采 PCM 自编 WAV（44 字节头 + PCM16），后端直接喂 numpy 给 faster-whisper，**省掉 ffmpeg 依赖**。

## 四、接口设计（草案）

### 1）语音识别

```
POST /api/voice/stt
  body: multipart/form-data  file=<wav 16k mono>
  → { ok, text, duration_ms, segments:[{start,end,text}], latency_ms }
```
- `segments` 保留时间戳 → 供 P3 的语速/停顿分析
- 模型可选：`tiny/base/small/medium`（默认 `small`，中文可用且体积约 500MB）

### 2）语音合成

```
POST /api/voice/tts
  body: { text, voice?, rate? }
  → audio/mpeg（mp3）
```
- 默认音色：`zh-CN-XiaoxiaoNeural`（面试官女声）；可切 `zh-CN-YunxiNeural`（男声/压力面）
- 失败兜底：前端 `speechSynthesis` 本地朗读

### 3）面试回合

```
POST /api/ai/interview
  body: {
    provider_id, stage, history:[{role,content}], profile,
    jd?, company?, role_persona, round_no, user_answer?
  }
  → { ok, reply, stage, round_no, quick_review?, finished? }
```
- 无 `user_answer` = 请求出题/开场；有 = 请求点评并追问或进入下一阶段

### 4）复盘报告

```
POST /api/ai/interview/review
  body: { provider_id, history, profile, jd?, metrics? }
  → { ok, content }    # Markdown 表格报告
```

## 五、提示词设计（草案）

### 5.1 面试官 system prompt（要点）

```
你是【<角色>】，正在面试候选人应聘 <岗位>（<公司>）。
规则：
1. 一次只问一个问题，口语化、简短（≤60 字），符合真实面试节奏。
2. 严格依据 JD 与候选人画像提问，禁止问画像中已有的信息（已知履历不要重复问）。
3. 追问遵循 STAR：回答缺数据/缺"你的角色"/缺结果时，必须追问一项。
4. 语气按角色：HR=温和流程化；大区总=业务犀利、追问数据；老板=格局与风险；压力面=质疑与反问。
5. 每题后给 ≤3 句即时点评（亮点 / 缺失 / 建议），再提问；不要长篇说教。
6. 不替候选人编造经历；不透露这是模拟。
7. 输出 JSON：{ stage, round_no, reply, quick_review, finished }
```

### 5.2 阶段与题量（可配置）

| 阶段 | 题量 | 关注点 |
|---|---|---|
| ① 开场与自我介绍 | 1 | 结构、卖点、时长 |
| ② 履历深挖 | 3–4 | STAR、数据、你的角色 |
| ③ 专业题（渠道岗） | 4–5 | 渠道搭建 / 经销商管理 / 回款与账期 / 库存动销 / 单店模型 / 空白市场下沉 |
| ④ 压力与动机 | 2 | 离职原因、稳定性、底线相关问题（拖欠费用、压货导向） |
| ⑤ 你的反问 | 1 | 考察提问质量 |

### 5.3 复盘报告模板（表格化，与雷达输出风格一致）

| 表 | 列 |
|---|---|
| 表一 · 总评 | 总分 / 等级 / 一句话结论 / 是否推荐进入下一轮 |
| 表二 · 逐题评分 | 题号 / 问题 / 你的回答要点 / 内容 / STAR / 数据 / 表达（各 0-5）/ 问题诊断 |
| 表三 · 更好的答法 | 题号 / 你的原话（节选）/ 改写示范 / 为什么更好 |
| 表四 · 表达节奏（P3） | 语速（字/分）/ 平均停顿 / 长停顿次数 / 口头禅次数 / 建议 |
| 表五 · 训练清单 | 优先补强点 / 具体动作 / 练习素材（结合画像与 JD） |

## 六、语音链路细节

| 环节 | 方案 | 备注 |
|---|---|---|
| 录音 | WebAudio `AudioContext` + `AudioWorklet`，重采样 16kHz、单声道、PCM16 | 兼容性优于 MediaRecorder（免 ffmpeg） |
| 识别 | `faster-whisper`（`small`，CPU int8 可跑；有独显自动加速） | 首次加载模型 2–5 秒；之后常驻内存 |
| 合成 | `edge-tts`（在线、免费、中文自然音色） | 失败 → 前端 `speechSynthesis` 兜底 |
| 权限 | Tauri capabilities 增加麦克风；WebView2 首次弹权限 | 未授权时给出引导与"仅文字模式"降级 |

## 九、隐私与合规

- 录音**默认只在本机内存中流转**，识别完成后即丢弃，不落盘、不上传第三方
- 使用本地 Whisper，语音不经过任何云服务
- 复盘报告只存本机 `data/interview/`；可一键删除
- 若未来切换云端 ASR：单独提示并默认关闭

## 十、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| WebView2 录音权限被拒 | 无法语音 | 引导开启 + 保留"纯文字面试"模式 |
| faster-whisper 依赖较大（ctranslate2 ≈ 数百 MB） | 安装慢 | 单独脚本安装，不装也能用文字模式 |
| CPU 识别慢（small 模型约 0.5–2× 实时） | 等待感 | 默认 `small`；可选 `base`；识别期间界面显示"识别中" |
| 4B/GLM-air 点评质量一般 | 复盘不够深 | 复盘报告交给 DeepSeek/强模型（按模块绑定模型，见后续"按用途绑定模型"计划） |
| Tauri 打包后模型路径 | 打包版找不到模型 | 模型存 `data/models/`，路径写入配置 |

## 十一、分期与验收

| 期 | 交付 | 验收标准 | 预估 |
|---|---|---|---|
| **P1** | 面试模式 UI + 多轮面试逻辑 + 复盘报告（**文字问答**，可选浏览器朗读） | 能完成一场 12 题面试并产出五张表的复盘报告；可带入机会池 JD | 2–3 天 / 10–20 万 token |
| **P2** | 本地 Whisper STT + edge-tts TTS + 权限处理 | 全程语音对练：点击说话→识别→播报；未授权可降级 | 2–3 天 / 10–20 万 token |
| **P3** | 表达节奏分析（语速/停顿/口头禅）+ 打断 + 多人格压力面 | 复盘中出现节奏指标；可中途打断面试官 | 3–5 天 / 20–40 万 token |

## 十二、后续可扩展

1. **针对具体公司的面试演练**：从机会池某条机会一键进入（JD + 公司背景 + 背调结论）
2. **题库沉淀**：把面试题与你的优秀回答写入知识库，形成"个人面试语料库"
3. **群面/多面试官**：两个角色交替提问（大区总 + HR）
4. **面试结果回流**：真实面试后录入反馈，反哺画像与短板分析
