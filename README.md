# 个人 AI 指挥中心 V1.0 · AI 猎头中枢

> 信息进入 · 知识沉淀 · AI 分析 · 人工审核 · 辅助决策 · 持续进化
>
> 中文优先 · 本地优先 · 不依赖 Dify · 数据只存本机

一个面向**求职操盘**的个人 AI 工作台：把「找机会 → 查公司 → 改简历 → 练面试」做成一条 AI 驱动、可审计、可分模块存档的流水线。

## 一、快速开始（三种方式）

| 方式 | 命令 | 说明 |
|---|---|---|
| **独立运行**（推荐） | 双击根目录 **`启动.bat`** | 首次自动建 venv、装依赖、构建前端；之后一键启动并打开 `http://127.0.0.1:8787`；关闭黑窗口即停止（也可用 `停止.bat`） |
| **桌面版**（原生窗口） | 双击 **`启动桌面版.bat`** 或 `cd frontend && npm run desktop` | Tauri 窗口；启动时自动拉起后端（8787 已占用则复用），关闭窗口一并结束后端；打包用 `打包桌面版.bat` |
| **开发模式** | `cd frontend && npm run dev`（5173）+ `cd backend && uvicorn app.main:app --port 8787` | 前端热更新，改代码用这个 |

**首次使用**：设置（`Ctrl+,`）→「模型直连」添加模型（DeepSeek / 智谱 GLM / 本地 Ollama）并「测试连接」→ 同一页配置搜索引擎（Tavily / 智谱 / Serper / Brave / 博查）→ **点「测试检索」确认能搜到再跑模块**。

> **检索忽然"没结果"？** 先点设置里的「测试检索」：一秒区分「额度用尽（Tavily 432 / 智谱 429）」「Key 无效（401）」「网络不通」。
>
> **首选免 Key 方案（本机实测可用，零注册）**：设置 → 搜索引擎选 **DuckDuckGo（ddg）** —— 实测 2.1 秒返回 5 条，直接搜到猎聘/BOSS直聘岗位页；
> 装依赖：`backend\.venv\Scripts\python.exe -m pip install ddgs`（或双击 `安装抓取增强.bat`，已包含）。
> 其他：Serper（免费 2500 次，实测网络可达）/ 博查（国内直连）/ 自建 SearXNG / 任意 MCP 检索工具。**Brave 与公共 SearXNG 实例在本机网络全部超时，不要白注册。**
>
> **DeepSeek API 不能用来检索**（实测确认）：它的 `/chat/completions` 只接受 `function` 类型工具（传 `web_search` 直接 422），
> `/responses` 的 `web_search` 内置工具被官方文档明确列为**忽略**，也没有独立搜索端点（`/web_search`→404）。
> DeepSeek 的联网搜索只在它的 App/网页版里有，**不对外开 API**。所以模型用 DeepSeek 没问题（你已经在用 `deepseek-flash`），检索必须另配引擎。
>
> **零额度也能出结果**：雷达/背调都有「手工粘贴材料」折叠框——用 DeepSeek App（免费带联网搜索）或浏览器搜到 JD、
> 公司风险、投诉内容，粘贴进去，照样跑「词库风险扫描 + 画像加权评分 + 六张表 / 18 维度报告 + 自动存档」，完全不调用搜索引擎。

**可选依赖安装**（不装也能用，只是少能力）：

| 脚本 | 装什么 | 获得什么 |
|---|---|---|
| `安装语音依赖.bat` | faster-whisper + edge-tts | 模拟面试的语音识别（本地离线）与语音播报 |
| `安装抓取增强.bat` | trafilatura（+ 可选 crawl4ai） | 抓取公开网页正文，补全 JD |
| `pip install mcp` | 官方 MCP SDK | 扩展中心接入 MCP 服务器（HTTP 传输用；stdio 用内置客户端） |

## 三、各板块功能逻辑

### 1. 岗位雷达（`RadarView`）

```
岗位关键词 × 目标区域 × 目标行业（均可多选，河南地市优先）
      ↓ 加上筛选项：薪资档位 / 经验 / 学历 / 公司性质 / 规模 / 发布时间 / 职位类型 / 福利标签
      ↓ 【结果数量】10 / 20 / 30 / 50 条（默认 20）→ 自动决定路数与每路召回
      ↓ 【手工粘贴材料】填了就直接跳过搜索引擎（零额度方案），材料同样进词库扫描与评分
      ↓ 组装最多 20 路检索：基础 8 路（区域×行业锚点 / 目标企业定向 / 平台聚合 / 领英 / 官网 / 硬条件 / 福利 / 企业质量）
        + 信号增强各 1–3 路（公司风险 / 扩张利好 / 雇主口碑 / 政策产业，四个开关默认全开）
        + 目标条数 >20 时按批次追加轮换的区域×行业路
搜索引擎（Tavily 原生域名+时间筛选；智谱用 site: 降级；**Serper / Brave / 博查 可选**）
      · 结果缓存 24h（同一查询重复运行不再消耗额度）；**排除词不再拼进查询**（会导致零召回）
      · 空路自动用「放宽查询」补检索；主引擎全空自动切备用引擎
      · 引擎报错且零材料 → 直接给出可操作错误（额度/Key/网络），不生成空报告、不烧 token
      ↓ 抓公开页正文：trafilatura → crawl4ai 可选；**磁盘缓存 24h + robots 遵守 + 并发 6 + 单次最多 16 页**；登录墙平台跳过
      ↓ 本地词库扫描（signals.py，不依赖模型）：风险 68 条 / 扩张利好 45 条 / 刷量 27 条 + 3 类计数规则
      ↓ 模型按画像权重打分：体系成熟度25 / 成长20 / 稳定15 / 渠道健康10 / 体量10 / 薪资10 / 团队5 / WLB5
输出 6 张表：表一机会池总表（**目标条数出满 + 去重合并 + 按级/总分排序**，含风险标记列）
        → 表二加权评分 → 表三逐条深度解析 → 表四风险·刷量·口碑 → 表五扩张利好与政策/产业 → 表六来源清单
      ↓ **表一不再以 14 列 markdown 表格呈现**：结构化成「机会池面板」——卡片视图（级色块 + 岗位/公司 + 薪资/福利/经验 chips +
        风险标记高亮 + 总分/分层 + 打开链接 + 详情展开）/ 紧凑表格视图，支持搜索、按级筛选、按级/总分/薪资排序、隐藏空行、导出 CSV
      ↓ 结果上方显示信号扫描面板；工具条显示「本批 N/目标 M · 第 K 批 · 路数 × 每路 · 累计去重 X 条」
      ↓ 「换一批」：自动排除已展示的「公司·岗位」，结果**追加到同一份报告**；「清空重来」重新累计
      ↓ 结果区可再点：投资视角深挖（VC 五步）/ 优秀企业筛选（6 步）
```

**结果数量与翻页（本轮新增）**

| 目标条数 | 路数 | 每路召回（自动） | 适用 |
|---|---|---|---|
| 10 | 14 | 5 | 快速扫一遍 |
| 20（默认） | 14 | 7 | 日常 |
| 30 | 17 | 12 | 一次看够 |
| 50 | 20 | 18–20 | 大范围铺开（搜索额度与耗时最高） |

每路召回也可手动指定（自动 / 5 / 10 / 15 / 20，引擎上限 20）。实测：目标 30 条 → **实际出 31 条**（17 路 × 每路 12）；点「换一批」再出 25 条，**与上一批重叠 0 条**，累计去重 56 条。

**四类信号增强与硬规则**

| 增强 | 做什么 | 硬规则 |
|---|---|---|
| ① 公司风险联动 | 检索材料里出现失信/被执行/欠薪/跑路/破产/投诉… 直接标注关键词 | 命中一票否决级关键词的岗位，「级」列最高只能是「低⚠️公司风险」，分层最高「谨慎」，**严禁进优先投递** |
| ② 扩张利好 | 融资/上市/并购/扩产/投产/技术突破/中标/出海 | 利好必须来自材料，且要判断「**是否真在扩人**」；不得拿公司名气当扩张证据 |
| ③ 雇主口碑 | 知乎/贴吧/投诉平台/公开转载（看准·脉脉是登录墙，只拿摘要） | 写清评价主题（提成/社保/加班/拖欠），材料未见就写未见 |
| ④ 政策与产业 | 国家/地方规划、扶持目录、重点产业链、以旧换新补贴 | 写清「哪份文件、哪一级、支持什么」；关键词可一键复制去官方渠道核对原文 |
| ⑤ 刷量排查 | 长期挂出 / 多平台重复 / 批量发布 / 猎头代招 / 薪资异常 / 收费陷阱 + 计数规则 | 命中即标「中⚠️刷量 / 低⚠️刷量」并给核实动作 |

> **关于"逆向爬虫"**：不做。绕过登录墙、验证码与站点风控违法风险高、极易失效，维护成本也不划算。
> 性能提升走合规路线：页面缓存（实测重复运行 4.15s → 0.10s，约 **41×**）、robots 遵守、并发限流 6、失败重试、
> 抓取页数上限 8 → 16、公开页正文抽取、搜索 API 召回。政策/工商/司法类信息以**官方公开渠道**为准。

- **画像来源**：`public/config/local-defaults.json`（候选人画像 + 求职优先级 + 底线 + 评分权重 + 定向企业）
- **合规红线**：只引用材料中**已公开招聘**的联系方式；禁止输出个人手机号；不抓登录墙平台、不绕过风控
- 详细逻辑见 [`docs/模块/01-岗位雷达.md`](docs/模块/01-岗位雷达.md)

### 2. 行业赛道（`IndustryView`）

**为什么单独成视图**：输入维度不同（行业而非岗位/公司）、结论要**长期跟踪**（蓝海两年后变红海，需要按行业存档对比）、且结论被雷达/深度分析/背调复用——所以做「一个视图 + 一个共享引擎」`industry.py`，不再各写一套。

```
行业 + 区域视角（可从岗位雷达一键带过来）
      ↓ 手填 17 个公开事实（需求信号/增速/融资数/政策/价格战/毛利/产能/玩家变化/招聘/薪资/技术替代/出海/区域产业基础…）
① 规则层：加权算分（需求 25 · 增速 15 · 政策 12 · 价格战 12 · 毛利 10 · 融资 10 · 产能 6 · 玩家 6 · 招聘 6 · 上市 5 · 补贴依赖 5 · 薪资 4 · 技术 4 · 出海 4 · 区域 4）
      ↓ 五档判定 + 硬性上限（政策强限制/恶性价格战/产能过剩/需求萎缩…）+ 新势力门槛（需求爆发 或 增速≥30%且融资≥15 起）
② 检索层：8 路（规模增速 / 融资 / 价格战 / 产能 / 政策 / 集中度 / 招聘 / 区域产业基础）
③ 词库层：阶段特征词交叉验证（**剔除检索式回显 + 按键词数归一**，避免把自己的提问算成行业特征）
④ 模型层：五节报告（赛道判定 / 需求与增速 / 竞争格局 / 政策与产业链 / 进入时机与个人动作），不得推翻规则层档位
输出：五档速查卡（当前档高亮）+ 分数与置信度 + 机会/风险/岗位与谈薪建议 + 各因子得分 + 相邻档位
      ↓ 报告自动存档到 data/knowledge/_行业/<行业>/，可按时间对比档位变化
```

| 档位 | 分数 | 一句话建议 |
|---|---|---|
| **新势力 / 风口期** | ≥80（过门槛） | 可进，但按风投标准：先问账上现金够发几个月、本轮融资到账时间、前任去向 |
| **蓝海朝阳（成长期）** | 65–79 | **最佳窗口**：体系搭建期，区域负责人价值与谈判空间最大 |
| **平稳存量（成熟期）** | 45–64 | 稳健：**只进龙头或细分第一**，重点问盘子多大、编制几人、考核是回款还是出货 |
| **红海内卷（饱和期）** | 25–44 | 谨慎：必须核实近一年提成实际兑现情况与账期，不接"无体系开荒"岗 |
| **夕阳没落（衰退期）** | <25 | 不建议：优先做能力迁移（渠道/客户资源可迁移） |

- 详细逻辑见 [`docs/模块/08-行业赛道.md`](docs/模块/08-行业赛道.md)（含全部权重、硬性上限、词库）
- **与画像联动**：定义为"成熟体系放大器"时，蓝海朝阳/平稳存量最优、龙头优先；新势力须核实现金与融资节奏；红海须核实提成兑现

### 3. 公司背调 + 风控体检（`BackgroundView` / `RiskPanel`）

**三层：先确定性、后模型**

```
① 规则层（risk.py，不依赖模型）
   手填公开事实（52 个字段：注册资本/实缴/成立时间/参保人数/被执行/失信/欠薪/劳动争议/同址企业/曾用名/已注销关联企业…）
      ↓ 阈值判定 → 红旗清单 + 风险分（0–100）+ 等级（绿/黄/橙/红）
      ↓ 一票否决 8 项：失信被执行人 / 严重违法失信 / 破产清算 / 吊销注销 / 欠薪黑名单 / 招聘收费 / 代理费加盟费 / 层级返利
② 检索层：8 路基础 + 10 路风控（空壳·换壳·实缴·欠薪·失信·舆情·税务·破产·投诉…）→ 抓正文 → 编号引用
③ 模型层：只做定性补充与话术，**不得推翻规则层数值**；规则层等级是下限，检索发现新的一票否决事实只能上调
④ 词库层（signals.py）：检索材料再扫三套确定性词库（风险 68 / 利好 45 / 刷量 27），命中项直接回传界面并在报告里逐条落位
```

- **两种跑法**：「完整背调」16 章（第 13 节强制写成 18 维度矩阵表 + 一票否决核查 + 待核实清单）；「只做风险体检」六节（总评 / 矩阵 / 一票否决 / 求职 Top5 + 面试话术 / 待核实 / 决策建议），更快更省
- **手工粘贴材料**：把从 DeepSeek App 联网搜索、企查查/天眼查公开页、裁判文书、投诉平台复制的内容粘进去 → 跳过搜索引擎，仍走词库扫描 + 规则层 + 报告 + 存档（搜索额度用尽时的零成本方案）
- **界面能力**：风控体检面板（按接口元数据自动生成表单、关键字段 12 项优先、一键规则判定秒回）、核查清单（每维度关键词 + 10 个官方查询入口）、报告存档列表（读/删）
- **输出**：风险等级徽章 + 红旗卡片（依据 / 核实动作 / 处理建议）+ 一票否决横幅；报告与事实快照自动归档到 `data/intelligence/<公司名>/`
- **另有按钮**：触点地图（公开渠道联系人 + 触达路径，七节）
- **合规**：只用手填公开事实 + 公开检索，不抓登录墙、不买号库、不采集个人手机号
- 详细逻辑见 [`docs/模块/02-公司背调.md`](docs/模块/02-公司背调.md)（含 18 维度清单与全部阈值规则）

### 4. 定制简历（`ResumeView`）


### 5. 模拟面试（`InterviewView`）—— 本项目最完整的一条链路

```
工作区：每场面试独立存档（左列表：搜索 / 标签筛选 / 重命名 / 删除 / 折叠）
配置：面试官人格（HR / 直属大区总 / 老板终面 / 压力面）+ JD + 音色语速 + 识别模型
      ↓
阶段流程 12 题：开场① → 履历深挖④ → 专业题④ → 压力与动机② → 你的反问①
      ↓ 每轮：面试官提问（分句流式播报）→ 你回答 → ≤3 句即时点评 + 按 STAR 追问
对话方式：① 连续对话（VAD 自动断句，免手点）② 单次录音 ③ 纯打字
      ↓ 连续对话支持打断（你一开口就打断面试官）
音轨：边说边显示（base 小模型增量识别 → 写入输入框，便于复盘）
      ↓ 说完 → small 模型正式识别 → 可选 LLM 轻校对（只纠同音字/行业词）
结束后 → 复盘报告五张表：总评 / 逐题评分 / 更好的答法 / 风险暴露 / 训练清单
      ↓ 自动存档（1.2 秒防抖）到 data/interview/<id>.json，可随时调取
```

- 语音链路：录音 → 本地 Whisper 识别（离线）；播报 → edge-tts（失败回退系统语音）
- 实测：small ≈0.8× 实时、medium 更准但 ≈2× 实时；默认 `small + 轻校对`
- 详细逻辑见 [`docs/模块/04-模拟面试.md`](docs/模块/04-模拟面试.md)

### 6. AI 助手（`ChatView`）

- 直连模型即问即答，Markdown 渲染，历史保留最近 60 条
- **允许调用工具**：勾选后走工具调用循环（最多 3 轮），模型自己选 MCP 工具；每条调用都有轨迹（工具/参数/结果片段）可审计；无可用工具时自动退化为普通对话

### 7. 扩展中心（`ExtensionsView`）

**MCP 服务器**（把成熟外部模块接进来）

| 能力 | 说明 |
|---|---|
| 常用预设 | 文件系统 / 网页抓取 / SQLite / Git / 长期记忆 / 结构化推理 / 浏览器自动化（一键添加） |
| 配置项 | stdio（后端用 npx/uvx 拉起）或 http（连已运行服务）、启用开关、免确认开关、备注 |
| 操作 | 测试连接（列出工具与耗时）、刷新工具清单、直接试调（JSON 参数） |
| 工程处理 | Windows 自动解析 `npx` → `npx.cmd`；npm 缓存重定向到 `data/cache/npm`；stdio 用自建 Popen 客户端（不依赖 asyncio 子进程） |

**技能（Skills）**：`data/skills/<name>/SKILL.md`（front-matter 写 title/description），内置 4 个：JD 拆解 / 简历定向润色 / 面试出题与追问 / 情报摘要与风险标记；支持新建、编辑、删除、**从 URL 导入公开技能**、试运行。

### 8. 设置（模型与检索）

| 标签页 | 内容 |
|---|---|
| 模型直连（推荐） | 供应商增删改（预设智谱/DeepSeek/Ollama/Kimi/Qwen）、逐个测试连接、选择默认模型 |
| Dify 工作流（可选） | 旧引擎，填地址与三个工作流 Key；各模块顶部可切换 |
| 搜索引擎 | Tavily / 智谱、时间范围、每路结果数、限定与排除域名、负词、正文抓取器（auto/http/crawl4ai）、跳过登录墙 |
| 语音参数 | 音色（3 男声 2 女声）、语速 6 档、识别模型（base/small/medium/large-v3） |

**模型路由（当前）**：本地 Qwen3.5-4B（Ollama，简单/隐私任务）+ DeepSeek API（深度分析）+ 智谱 GLM（备用）——全部按模块在界面上切换。

## 四、数据存储与目录约定（**按板块分开存储**）

原则：**配置与业务数据分离、每类数据一个目录、原始数据永不覆盖**。

```
data/
├── config/         # 配置（含密钥，全部不入 git）
│   ├── ai.json        模型供应商（含 API Key）
│   ├── search.json    搜索引擎与筛选默认值
│   ├── voice.json     语音参数（音色/语速/识别模型）
│   ├── mcp.json       MCP 服务器配置
│   └── contact.json   触点地图：付费工商数据源预留位
├── interview/      # 【模拟面试】每场一个工作区 <id>.json（标题/标签/消息/复盘/时间）
├── skills/         # 【扩展中心】技能库 <name>/SKILL.md
├── models/         # 本地模型：whisper（语音识别模型）、hf（下载缓存）
├── cache/npm/      # MCP 服务器依赖的 npm 缓存（随项目迁移，不污染系统）
├── inbox/          # 收件箱：未整理的原始素材（JD、聊天记录、截图文字）
├── knowledge/      # 长期知识库：方法论/行业认知/模板（已作为 /api/knowledge/stats 默认路径）
├── intelligence/   # 情报与背调：公司背调、行业简报、触点地图
├── projects/       # 项目/求职进程：一个机会一个目录（JD+简历版本+面试记录+时间线）
├── decisions/      # 决策记录：关键选择与依据（含复盘日期）
├── review/         # 复盘：日/周/月、面试复盘
├── database/       # 结构化数据：CSV/JSON/SQLite（岗位库/公司库/联系人库）
└── logs/           # 运行日志副本（可随时清理）
```

> 上述 8 个知识型目录**已建好**，每个目录内都有 `README.md` 写明用途、命名规范与流转关系；
> 建议的流转链路：`inbox/`（原始）→ `knowledge/`+`intelligence/`（认知与情报）→ `projects/`（行动）→ `decisions/`+`review/`（选择与复盘）→ `database/`（可查询沉淀）。

| 存储层 | 用途 | 位置 |
|---|---|---|
| 后端配置 | 模型/搜索/语音/MCP | `data/config/*.json` |
| 业务存档 | 每场面试独立工作区 | `data/interview/<id>.json` |
| 技能库 | SKILL.md 指令包 | `data/skills/<name>/SKILL.md` |
| 本地模型 | Whisper 模型与 HF 缓存 | `data/models/` |
| 知识沉淀 | 收件箱 / 知识库 / 情报 / 项目 / 决策 / 复盘 / 表格数据 | `data/{inbox,knowledge,intelligence,projects,decisions,review,database}/`（各自 `README.md` 有规范） |
| 前端临时状态 | 表单输入、视图、聊天历史、折叠状态 | 浏览器 localStorage（换机不同步） |

> 详见 [`docs/数据存储约定.md`](docs/数据存储约定.md)；`.gitignore` 忽略 `data/` 全部内容（仅保留各目录的 `README.md` 说明），确保密钥与个人数据不入库。

## 七、已知限制与合规边界

| 系统代理 | 若开着代理，请把 `127.0.0.1` 加入例外，否则可能出现 503 |
